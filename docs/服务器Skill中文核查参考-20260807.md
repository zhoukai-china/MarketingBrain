## 三、重复与边界判断

没有发现完全重复的 Skill ID 或同一份提示词被以不同名称重复暴露。以下是容易被用户感觉“重复”的相邻能力，建议在智能体路由和前端文案中明确区分：

| 容易混淆的能力 | 正确边界 |
| --- | --- |
| `baolu_content_creator` / `baolu_topics` / `moments_generator` | 分别负责完整内容生产、选题、朋友圈私域文案。先选题，再创作，再按需改写朋友圈。 |
| `baolu_review_engine` / `baolu_live_review_engine` | 前者复盘短视频，后者复盘直播数据；输入数据类型和指标不同。 |
| `commerce-clip-editor` / `persona-clip-editor` | 前者偏商品/成交内容，后者偏创始人或人设表达。 |
| `restaurant-growth-advisor` / `takeaway-growth-advisor` / `menu_optimizer` | 分别是堂食经营、外卖经营、菜单工程；其中 `menu_optimizer` 目前仍是占位，不能路由过去。 |
| `ip_positioning` / `brand_consultant` / `yuanshen_factory` | 分别是个人 IP 定位、品牌咨询、数字分身生产；其中 `brand_consultant` 当前不可对外用。 |
| `sales_growth_advisor` / `franchise_recruitment_system` | 前者服务成交与销售团队，后者服务加盟招商链路。 |

## 四、质量分层与发布建议

### A. 可作为第一批对外能力（22 个）

内容、视频、直播、短视频复盘、选题、IP、销售、餐饮、外卖、CEO 经营分析、交付、招商、HR、财务等已具备专用提示词的 Skill。对外前仍应做固定案例验收，尤其是财务、HR、合规类内容必须有边界提示。

### B. 仅限内测（1 个）

`ai_daily_brief`：提示词只有基础格式要求。建议补齐：允许的数据源、信息日期、引用链接、无法验证时的表达方式、行业/城市筛选、重复新闻去重规则。

### C. 暂时下线或隐藏（11 个）

`brand_consultant`、`digital_twin_factory`、`franchise_compliance_checker`、`management_consultant`、`menu_optimizer`、`multi_store_dashboard`、`opc_client_education`、`opc_delivery_system`、`opc_pricing_model`、`promotion_planner`、`store_data_analyst`。

原因：它们的线上文件是占位说明，不包含完成的专业工作流、输入追问规则、输出格式、样例或质量边界。若被调用，用户得到的将不是对应专业服务，容易损害产品信任。

## 五、什么叫“高质量输出”

不能只看文档篇幅，也不能只看模型某一次回答是否好看。每个要对外开放的 Skill 至少应满足：

1. **输入明确**：知道缺少哪些关键资料时必须追问，而不是编造。
2. **输出可执行**：给出表格、步骤、优先级、负责人、时间、预算或指标，而不只是泛泛建议。
3. **有领域边界**：财务、HR、合规、医疗、法律等要说明不能替代专业人士，且不得虚构法规/数据。
4. **可核验**：涉及事实、行业数据、新闻或竞品时，附上来源与日期；没有可靠来源时明确标注“待验证”。
5. **可复现**：同一类型输入应稳定遵循相同的框架；至少保留 3 个通过验收的样例。
6. **有拒答和降级策略**：信息不足、超出权限、请求高风险内容时，知道如何澄清或安全拒绝。

## 六、建议的确认顺序

1. 先在路由中隐藏 11 个占位 Skill，避免 WorkBuddy、微信和思潼前端误调用。
2. 用 22 个可用 Skill 各跑 3 个真实业务案例：信息完整、信息不足、边界/高风险输入。
3. 为每个 Skill 建立一页“验收卡”：适用场景、必填输入、标准输出、禁止事项、三个合格样例。
4. 最后再决定哪些 Skill 出现在 WorkBuddy 的 `sitong.skills` 列表和用户可见的功能入口。

## 七、本次核查的边界

本次确认的是“生产服务器当前存在且 MCP 可加载的 Skill”，并对文件结构与内容成熟度进行了审查；没有逐一调用大模型生成 34 份真实业务答案。因此，22 个“可用”代表具备发布候选资格，不等于已经完成所有行业案例的最终质量验收。
