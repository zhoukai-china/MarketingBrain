## 一、需求一句话

对话过程中，用户提到（或 AI 判断其有）「找真人咨询师入企 / 陪跑」需求时，自动推送官方客服企微二维码卡片，转人工跟进。

## 二、两层架构（实现时照此拆）

1. **判断层 = skill / 模型**
   - 显式信号（提到即触发）：找真人 / 真人咨询师 / 人工客服 / 转人工 / 咨询师上门 / 入企 / 驻场 / 线下咨询 / 见面聊 / 当面聊 / 加微信 / 联系方式 / 找保禄本人
   - 隐性信号（结合上下文判断）：反复议价砍价、要求定制专属方案、强调企业情况特殊、询问签约合作流程、索要报价单
   - 命中后只输出固定信号 `[TRANSFER_HUMAN]` + 一句引导话术；**模型不输出二维码图片**
2. **执行层 = 产品端**
   - 监听 `[TRANSFER_HUMAN]` → 对话流插入客服卡（企微码图 + 备注暗号「入企」+ 引导文案）
   - 码图从后台「客服活码配置」接口读取——运营资产可换码、分渠道投码、统计来源，**不写死在 prompt / 前端**
   - 推送后对话不中断；后续消息重新走判断

## 三、实现要点

- **转人工判断优先于域外守卫**：「你们能派人到我们公司吗」不是新媒体问题，但它是销售线索，必须接住，不得以「只答新媒体相关」为由拒绝或瞎答
- **线索埋点**：记录会话 ID / 触发消息原文 / 命中信号类型（显式 or 隐性 + 具体词），供销售跟进复盘
- **优先级顺序**（demo 的 route 顺序可参考）：文件交付意图 → 转人工判断 → 元问题 → 决策类 → 追问 → 七域 → 域外守卫
- 素材：客服企微码已定稿（思潼 / 蓝策咨询 · 思潼AI商城官方客服），demo 内为 base64 内嵌固定码，正式实现改为活码接口下发

## 四、验收标准

- [ ] 用户说「找真人 / 能派人上门吗 / 加个微信」→ 对话流出现客服企微码卡片
- [ ] 议价类消息（"能便宜点吗 / 报个价"）→ 同样触发
- [ ] 「线下门店怎么引流」等正常新媒体问题 → 不误触发
- [ ] 触发时有埋点记录（会话 / 消息 / 信号类型）
- [ ] 后台可更换码图（活码配置），无需改 prompt 或发版
