## 1. 背景与现状

- 现线上入口：`https://ai.lcppch.top/agent/ipzone__ip-pos/chat`，纯对话逻辑。
- skill（ip_positioning）已有很好的「6 步逐轮访谈 → 确认卡 → 速览 + 8 章全案」机制，SKILL.md 的访谈引导、消化确认、固定输出合同全部**保留**，工作台只是换壳不换魂。
- 已在生产的计费/交付链路（ppu 400 积分/次、deliverabilities → deliverables 30s 轮询 + 25 分钟超时）**沿用不动**。
- 参考先例：文案工作台原型 `docs/prototypes/copy-workbench-demo-20260922.html`（本次 demo 复用其 JS 架构）。

## 2. 核心设计（demo 已完整演示）

**布局**：左（390px）= 沈定 6 步访谈对话；右 = ① 定位简报 8 字段（实时点亮）② 三态画布（锁定占位 → 生成中逐件点亮 → 交付 9 件分区卡片）。

**六个维度的升级**（对照表如下）：

| 维度 | 现在 · 纯对话 | 升级后 · 工作台 |
|------|------|------|
| 信息收集 | 用户自己组织一段话，易漏要素 | 6 步访谈逐维引导，简报 8 字段强制齐全，缺项【待补】标记 |
| 确认环节 | 确认卡埋在对话流里 | 简报常驻右侧，生成前最后一眼确认，点字段即改 |
| 过程可见性 | 8 章长文流式输出，黑盒 | 9 卡逐张点亮 + 生成日志（定位三角/JTBD/五维人设/矩阵配比） |
| 结果形态 | Markdown 长文，复制易漏 | 5 分区 9 件卡片，单章复制/单章重生成/整包导出 |
| 迭代方式 | 重新对话描述改动，不可控 | 点字段改简报重跑全案，或单章重生成 |
| 计费透明 | 400 积分一次扣完 | 400 积分 = 9 件件件可见；402 文案统一「积分不足，本次未消耗」 |

**简报 8 字段**（6 步访谈映射，第 2/5 步一次答两字段）：角色 / 项目 / 商业模式 / 竞争格局 / 目标用户 / 创始人 / IP目标 / 现状与投入。

**交付 9 件 5 区**：⓪速览区（1分钟速览）· 定位区（一、项目定位 / 二、目标用户定位）· 人设区（三、IP人设定位）· 内容区（四、内容定位 / 五、选题方向）· 增长区（六、投流建议 / 七、IP发展规划 / 八、执行建议）——对应 skill 固定输出合同。

**双轨输入**：新手走 6 步访谈（自动预填简报）；老手可点字段直改、输入框打字（「竞品换成 XX」→ 简报更新）、或「跳过访谈」一键填示例简报。chat 能力不降级。

## 3. 工程改动点（建议实现路径）

1. **前端**：新增路由 `/agent/:sku/workbench`（AgentChatPage 保留 `/chat` 兜底，workbench 设为默认）。工作台 = 访谈组件 + 简报状态 + 分区交付渲染三块。6 步问题模板第一期前端内置，demo 内 `QFLOW` 数组即可作 schema（每步 `{fields, q, hint, digest, opts}`）。
2. **后端/接口**：run 接口不变（`POST /api/market/skus/:skuId/run`）；交付轮询复用 `deliverabilities → deliverables`；answer 由纯 Markdown 升级为带章节标记的结构化输出（如 `<!--PIECE:ch3-->`），前端按标记渲染 9 张分区卡片（demo 内 `PIECES` 数组是卡片 schema：`{id, no, g, gt, icon, title, d, gd, html, plain}`）。
3. **计费**：全案沿用 ppu 400；单章重生成需在 run 接口加 piece 参数白名单（口径见待确认 ①）。
4. **顺手修 QA 遗留**（20260917 QA 报告两条低优文案）：开场白「5 轮」→ UI 明确「第 X/6 步」（demo 已示范）；低积分 402 提示统一「积分不足，本次未消耗，请充值后重试」。
