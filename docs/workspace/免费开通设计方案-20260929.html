「免费开通」设计方案

思潼AI商城首页 Hero 主 CTA：🧧 免费开通 · 立送 100 算力  ·  2026-09-29 提案（未落代码）
结论先行（推荐方案 A）：Hero 的「免费开通」= 一键激活账号并领取注册礼 100 赠送算力，用弹层两步走（手机号验证 → 到账）， 拿到后就地引导首单（挑一个数字人直接用）。不是一个独立开通页，也不做成静默领取。 它和右侧「邀请有礼」彻底分家：Hero = 我开通领 100；邀请位 = 拉人各得 100。

1. 现状与问题

项现状问题
点击行为点「🧧 免费开通」打开的是邀请海报弹层（EcoMallHomePage → setShowInvite(true)）文案与行为错位：我说开通，你给我拉人
开通态没有「已开通 / 待领取 / 已过期」的状态区分，所有人看到同一个按钮老用户也看到"免费开通"，语义失真
赠送落账未实现。赠送账本（bonus 桶 + 90 天有效期）已在 sitong-wallet 就位，但没有"注册礼"发放入口CTA 是空的，点了没有真实权益
风控无（同设备/同手机号/同支付账号只认一个的规则没接入）可被批量薅

2. 口径依据（HANDOFF 算力计费规则 v1.0）

  • §2.1 智能体 0 元开通：不收开通费、无月费，每次使用按目录价扣算力 → 「免费开通」指的是开通账号 + 领注册礼，不是"买会员"。
  • §7 赠送算力统一属性：来源含注册礼 100；90 天有效期、到期清零、到期前 3 天提醒；限文字类任务使用（视频生成不可用/限抵 50%）；不计入佣金基数。
  • §2.7 扣减顺序：赠送先扣（到期最近优先），充值后扣 → 注册礼会被最先花掉，才是"开通即能试"的体感。
  • §8 邀请裂变：好友注册+手机号验证立得 100（赠送）；邀请人待好友累计真实消耗满 50 再得 100 → 注册礼和邀请礼是两笔，不可混为一个弹层。
  • §2.6 保护：余额 <50 预警；单日累计 100 提示确认一次。

3. 三个方案对比

方案形态优点缺点
A 推荐弹层两步走 Hero CTA → 开通弹层（手机号/微信授权）→ 成功态（100 已到账 + 到期日）→ 首单引导 不离开首页、转化路径最短；状态可分支（未开/待领/已领/已过期）；赠送规则在弹层内讲清楚 需要新弹层组件 + 一个后端接口
B独立开通页 跳 /activate 专属页，含权益说明、开通、首单推荐 信息承载多，适合投放落地页/SEO 离开商城主路径，首单转化多一次跳转流失
C静默领取 已登录即视为已开通，CTA 变「领取 100 算力」，点一下直接入账 零摩擦 没有手机号/实名锚点，风控无从下手，易被刷；也讲不清赠送规则

5. 开通弹层结构（方案 A 的前端）

表单态

  • 标题：0 元开通 · 立送 100 算力
  • 字段：手机号 + 验证码（60s 重发）；已登录则显示当前账号、只需确认
  • 权益卡（三条，照 §7）：
    ① 100 算力 · 赠送性质 · 90 天有效
    ② 限文字类任务（视频生成不可用）
    ③ 不收开通费、无月费、用多少充多少
  • 按钮：确认开通 · 领取 100 算力（橙渐变）
  • 细则小字：同设备/同手机号/同支付账号仅一份；异常挂起审核（照 §8.2）

成功态

  • ✅ 大字：100 算力已到账
  • 副行：赠送算力 · 有效期至 YYYY-MM-DD（90 天后）· 到期前 3 天提醒
  • 余额条：充值 X · 赠送 Y（+100）
  • 首单引导三选一（卡片，点进去直接用）：
    秦文 15 算力/次 · 沈定 99 算力/份 · 何策 99 算力/次
  • 次级按钮：先逛逛（关弹层回首页）

6. 后端契约（新增，最小可用）

POST /market/activate（登录态可选；未登录时带手机号+验证码）

项约定
请求{ phone?, code?, inviteCode? }
响应{ activated: true, gift: { amount: 100, bucket:"bonus", expiresAt, scope:"text" }, wallet: { paid, bonus } }
幂等按 userId（无用户则按手机号）只发一次；重复调用返回已发记录，不重复入账
入账走 sitong-wallet：bucket="bonus"、type="bonus"、source="signup_gift"、expiresAt = now + 90d（与充值加赠/签到同一口径）
扣减不改现有顺序：赠送先扣（到期最近优先）——已在钱包实现，注册礼自然最先被花掉
风控同设备 / 同手机号 / 同支付账号只认一份；单日激活量异常 → state="pending" 挂起，人工审核后发放（照 §8.2）
错误码code_invalid / already_activated / risk_hold / rate_limited
账单流水含构成（赠送/充值），后台「算力管理」可查这笔 100（type=bonus, source=signup_gift）

注：赠送算力不计入合伙人佣金基数（§6），发放接口写入时带 countCommission:false 标记，避免后续佣金统计被污染。

7. 与邀请 / 签到的边界（避免三件事糊在一起）

入口得什么条件位置
免费开通（本方案）注册礼 100 赠送开通 + 手机号验证，每人一次Hero 主 CTA（橙底白字大按钮）
邀请有礼好友 100 + 邀请人 100好友注册验证立得；邀请人待好友累计真实消耗满 50Hero 下方广告位（海报 + 复制链接）
每日签到5 / 天，第 7 天 +30，周封顶 60断签重置侧栏或首页小入口（后续 A 线 P1）
三条都落进同一个赠送账本（90 天有效、限文字类、不计佣金），只是 source 不同：signup_gift / referral_reward / checkin。
