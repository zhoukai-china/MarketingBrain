一次出片的四个接口：各自干嘛，时间去哪了

模式 生成已 mock（不调阿里云百炼） 实测 你刚跑的这一次（DevTools 数字） 日期 2026-10-04

一句话：生成是 mock 的，所以「等阿里云出片」的几分钟被压成了 0；剩下的时间几乎都花在把你的原片和肖像照真·上传到阿里云 OSS 暂存桶——这一步就算生成是 mock，也是真实网络，因为「素材只进你自己的桶」是定死的设计。

POST /quote 校验+报价 114ms

干嘛：检查四项授权与素材是否齐全、读租户 owner 钱包余额、按 24 算力/秒算出本次价格（48 算力）。

快的原因：全程本地——数据库查询 + 内存计算，不碰任何外部网络。

POST /confirm 创建出片任务 5.07s

干嘛：真正下单——把原片 + 肖像照上传到生产 OSS 暂存桶、钱包扣 48 算力、创建任务、提交「生成」。

慢的原因：OSS 上传是真网络（几 MB 走家庭宽带上行）；「提交生成」这步已是 mock、瞬间完成。

POST /refresh 推进任务 2.08s

干嘛：查一次生成结果 → 把成片落盘并 ffprobe 校验（时长/分辨率/h264）→ 结算（reserved→charged）。只轮询了一次就拿到 SUCCEEDED。

慢的原因：成片校验是真功夫——ffprobe 探测、读回哈希比对、结算事务，外加一次 OSS 往返。mock 的「查结果」本身是 0 耗时。

GET /content 取成片 229ms

干嘛：从平台本地磁盘把 1.4MB 的成片字节流给浏览器，供播放与「下载成片」按钮。

快的原因：纯本地磁盘读 + 登录态校验；成片已在自己服务器上，不需要再去任何外部取。

为什么中间两个慢 · 时间去向

confirm 的 5.07s

大头是 把原片和肖像真·上传到生产 OSS 暂存桶——生成虽然 mock 了，但「素材只进你自己的桶」是定死的合规设计，这步永远是真网络。从日志看单次 OSS 往返就要 ~220ms，PUT 整个视频按体积累积。剩下是钱包扣费、建任务（本地 DB，毫秒级）和 mock submit（瞬间）。精确分解可在 dev 终端搜 beauty_video.oss 事件看 elapsedMs。

refresh 的 2.08s

mock 让「查结果」变成 0 耗时，剩下的 2 秒是成片校验的实打实动作：ffprobe 探测时长/分辨率/编码、读回哈希比对、结算事务，外加 admission 复查时的一次 OSS 往返。

和真实链路差在哪

真实出片时：confirm 依旧 ~5s（OSS 上传不变）；refresh 之间会隔 15 秒轮询多次、总耗时 = 阿里云生成的几分钟。mock 把「那几分钟」压成了 0，其余时间一个子都没省——所以你现在测到的交互节奏（点完 5 秒受理、再 2 秒出片）已经非常接近真实上线的体感，只是把「干等生成」拿掉了。

口径：quote/confirm/refresh/content 为前端 DevTools 实测数字；OSS 往返耗时取自后端日志 beauty_video.oss 事件（HEAD 实测 ~220ms，曾观测到一次 20s 超时导致单个 refresh 503、下次自愈）。「生成接口」一列是被 mock 替代的阿里云百炼视频生成。
