skill 的真实边界（本项目实况）

查了代码后的结论：skill 本身只提供「提示词文本 + 质量契约」，被运行时「选中」使用；它不写工具配置，也做不到让模型在对话里主动调工具/知识库。
能力配置写在哪谁触发模型是否主动
skill 提示词prompt.md → DB 快照运行时「选中」被动（被拼进请求）
知识库agent 的 marketing.knowledgeAction用户点按钮否（文档注入上下文）
工具MCP 协议层（外部）外部系统 / 自动化否（非对话内）
纠正我之前的说法：我前面说「skill 在 agent loop 里让模型主动调知识库/工具」是错的。本项目大模型调用是单次 completion，provider 把 tool_calls 当异常处理；agent-runtime 没有模型循环调工具的代码。skill 只是被「选中」后拼提示词调一次模型。所以严格说：skill 既不能让模型主动调知识库，也不能让模型主动调工具。
