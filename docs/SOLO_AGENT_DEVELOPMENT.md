# 一个人开发三个智能体：使用说明

## 你最简单的使用方式

你不需要判断需求属于前端、后端、数据库、公共能力、Prompt 还是 Skill。直接在当前任务告诉 Codex：

```text
产品是谁 + 现在的问题/想要的结果 + 你怎么判断它做好了
```

如果第三项说不清也没关系，Codex 会根据当前产品契约补成可验证的验收条件。Codex 负责归类、建任务卡、选择文件、先写回归、实现、测试和更新交接文档。

例如：

| 你说的话 | Codex 自动归类 |
|---|---|
| “外卖诊断完以后，要能按问题做七天实验” | 外卖 `TW` 产品任务 |
| “招商选题把门店获客内容混进来了” | 品牌招商 `FA` Bug 与边界回归 |
| “蓝旗加盟商要能邀请一家美容院开通” | 蓝旗 `LQ` 任务，包含平台租户/邀请子改动 |
| “三个智能体重复扣算力” | 公共平台 `PLAT` Bug，三个产品做相邻回归 |

## 文件到底放哪里

- 所有可运行源码只在 `F:\思潼AI增长os\baolu-os-v2-source` 开发。
- 产品定义、任务卡、状态和专项测试说明放在 `docs/agents/<产品>/`。
- 客户提供的蓝旗原始资料属于客户项目资料，不直接当源码；完成授权、脱敏、结构化和审核后，才通过知识导入能力进入产品。
- 归档、快照、发布包和备份只作证据或恢复来源，不能在里面继续开发。
- Codex 会判断最终代码应该进入 `apps/web`、`apps/api`、`packages/*`、`prisma` 或 `mcp-skills`，用户不用选择。

## 什么情况继续当前任务

以下情况留在当前任务：同一个产品、同一个用户结果、同一个 Bug 的复现与修复、对刚完成结果的补充验收。例如“招商 Brief 保存失败”修好后又发现刷新丢失，仍属于同一结果。

以下情况建议新开左侧任务：换了智能体、换了独立用户结果、需要与当前工作长期并行、或要做公共平台级改造。Codex 会先给出建议标题、任务编号、原因和应读取的任务卡；只有你明确要求创建时，Codex 才会创建新任务，不能把当前消息静默搬过去。

上下文太长时，不靠复制聊天记录交接。Codex 把当前事实写进任务卡和 `STATUS.md`，新任务只读取仓库中的当前源码、产品文档、任务卡、测试结果与未解决风险。聊天只负责沟通，仓库文件才是可验证的交接依据。

## 可以同时开发吗

可以，但一个人开发时最多同时进行两个编码任务，并满足：

- 必须是不同智能体，例如一个外卖任务加一个品牌招商任务。
- 使用不同 worktree，避免两项修改互相覆盖。
- 两项都要改公共热点文件、数据库结构或统一路由时，改成串行。
- 同一智能体同一时间只做一个编码结果。
- 知识整理、产品定义、Eval 设计可以和另一个智能体的编码任务并行。

## Codex 每次如何完成任务

```text
接收自然语言需求
→ 自动选择 TW / FA / LQ / PLAT
→ 建立一张结果任务卡
→ 写正常、失败和禁止结果
→ 运行修改前基线
→ Bug 先增加失败回归
→ 实施最小改动
→ 运行领域专项 + 仓库门禁
→ UI 用真实浏览器走用户旅程
→ 更新任务卡和产品状态
→ 报告证据、未运行项和风险
```

任务不再按“一个按钮一个对话框”拆分。合理粒度是一个可交付的用户结果，例如“完成招商 Brief 并可保存恢复”，其中自然包含页面、接口、数据和测试。

## 你仍然需要决定的事情

Codex 可以替你做技术归类，但不能替你决定商业授权：蓝旗哪些知识可以给哪些角色、内部定价的生效与失效、谁承担充值和退款、何时允许真实发布/付款/发消息，以及最终业务内容是否代表蓝旗。这些决定确认一次后会写入产品契约，不需要每次重复解释。
