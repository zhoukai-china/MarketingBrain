## 模型与推理策略（2026-08-20 冲刺追加）

- 目标简报理解、四来源证据综合、目标一致内容生成、多轮语义修正和高风险事实/目标复核固定使用当前网关已批准的 Pro 档模型；本机当前配置为 `deepseek-v4-pro`，任务标签为 `reasoning_high`。
- `deepseek-v4-flash` 只能在同一脱敏 Eval 已证明分类、字段提取或格式转换不降低质量后，作为 `reasoning_standard` 的低风险候选；本任务不自动启用。禁止其他低端 DeepSeek、百炼文本或固定模板静默降级。
- 招商承诺、收益、价格、疗效、案例、政策与投流预算均属于高风险内容：必须保持 Pro、事实边界和人工确认门禁。模型不可用、超时或质量不合格时 fail-closed，明确待补或重试。
- 每次真实运行必须可审计实际 provider/model、任务阶段、延迟、成功/失败与降级状态；内部 Eval 使用隔离租户且不得扣正式租户积分。该通用审计字段由网关共享层交接，本任务不修改其公共实现。

## 验收条件

1. 正常路径：四目标各两例、同一选题切换四目标后均产生目标专属的可编辑内容成品；内容包含选题/钩子、目标人群、来源依据和事实边界、获客关系、正文与目标专属 CTA。
2. 失败路径：缺素材、模型超时/失败、重复点击、刷新恢复、返回重选均明确且可恢复；不把失败文本或通用旧结果写入草稿。
3. 不应发生：旧通用会话、其他目标、其他主体或其他租户资料进入生成；编造案例、收益、数字或已执行动作；自动投流、发布、付款。
4. 可观测结果事件：FIP 草稿生成请求、通过/拒绝原因、保存、恢复；事件只记录目标与状态，不记录客户原文。

## 基线与失败证据

- 基线命令：`pnpm.cmd tsx scripts/founder-ip-content-context-isolation-smoke.ts`、实际 FIP 草稿生成路径。
- 修复前失败测试/Eval：专属回归要求 FIP 生成不得通过通用 `send()` 携带工作台历史，并要求存在受租户保护的 FIP 生成接口；旧实现不满足。
- 现象、根因和连带影响：草稿创建后仍由 `runContentSystem()` 调用通用 `send()`，后者携带旧任务历史并进入通用内容交付链；旧最终门禁把待核验来源一律拦截为待补草稿，导致正确目标也无法产出可用成品。
