# 兰琪知识治理

## 四层知识

| 层级 | 内容示例 | 默认可见范围 | 是否可进入全局兰琪知识 |
|---|---|---|---|
| K1 兰琪授权核心知识 | 方法论、项目逻辑、获客成交方法、受控内部定价 | 兰琪授权明确覆盖的租户 | 经兰琪审核后可以 |
| K2 兰琪总部私密知识 | 总部经营数据、未公开政策、渠道名单、内部管理资料 | 兰琪总部指定角色 | 不可以下放 |
| K3 门店私有知识 | 本店客户、流水、员工、活动和执行结果 | 当前门店租户 | 不可以 |
| K4 任务临时上下文 | 本次上传、草稿、临时分析材料 | 当前授权会话 | 不可以 |

## 每条受控知识的最小元数据

- `knowledgeId`：稳定标识。
- `owner`：兰琪或明确权利人。
- `version`：可回滚版本。
- `source`：原始资料或批准记录的可追溯引用。
- `scope`：允许的角色、租户类型、门店或渠道。
- `effectiveFrom` / `expiresAt`：生效与失效时间。
- `applicability`：区域、项目、门店类型和前置条件。
- `sensitivity`：核心授权、总部私密、门店私有或临时。
- `reviewer` / `approvedAt`：业务审核证据。

## 反馈进入知识库的规则

门店反馈先去标识化并转成候选案例。单一门店偏好不能自动升级为兰琪全局规则；真实经营结果也不能携带门店身份进入其他租户上下文。只有兰琪业务复核、离线 Eval、质量门禁、批准和可回滚发布完成后，候选才可以成为新的 K1 版本。
