# 兰琪智能体开发流程

## 开发顺序

兰琪当前先做产品和知识基础，不能直接从页面按钮开做。

```text
LQ-01 授权契约
→ LQ-02 知识结构与版本
→ LQ-03 租户、推荐与开通
→ LQ-04 门店经营档案
→ LQ-05 经营诊断
→ LQ-06 项目、获客与成交
→ LQ-07 算力钱包与复盘
```

每个编号是一个可以独立验收的结果。一个任务完成输入契约、服务逻辑、页面路径、失败处理和回归测试，不再把同一结果拆成“做按钮”“接接口”“再手测”三个互相脱节的任务。

## 每个任务的固定闭环

1. 从 `tasks/` 中建立任务卡，写清用户结果和不应发生的结果。
2. 读取当前授权规则、知识版本、产品契约和相关源码。
3. 建立正常、缺资料、无权限、跨租户、工具失败和重复请求样例。
4. 保存 Champion 基线；Bug 任务先证明新增回归会失败。
5. 一次只改变一个主要变量，实施最小改动。
6. 运行兰琪专项检查、`qa:fast` 和与风险匹配的回归。
7. 页面任务必须真实操作桌面和移动核心路径。
8. 更新任务卡和 `STATUS.md`，留下下一任务可直接读取的交接证据。

## 知识上线流程

```text
兰琪提供资料
→ 确认所有权、授权范围和有效期
→ 去除客户隐私与无权内容
→ 结构化并标注来源/版本/适用条件
→ 建立检索与拒答 Eval
→ 兰琪业务负责人复核
→ 测试租户灰度
→ 批准后激活
```

每日学习或用户反馈只能生成脱敏样例、评分、聚类和改进候选，不能自动修改或激活生产知识、Prompt、Skill、路由和代码。

## 双入口与后续产品顺序（2026-09-03 更新）

```text
LQ-15 兰琪小红书图文生成（已完成统一网页闭环）
→ LQ-17 同一问答能力独立网页 + WorkBuddy 薄适配（已完成；小红书后续开发暂停）
→ 兰琪 WorkBuddy 外部连接验收：只验证 Connector/OAuth、最小权限和双入口恢复
→ 其他问答扩展 / 视频能力（后续）
```

独立网页与 WorkBuddy MCP 调用同一个兰琪后端 capability、Agent/Skill、知识、租户权限、积分账户和 usage ledger。MCP adapter 不复制提示词或业务逻辑。余额不足、凭据过期、权限不符、超时、取消和重复请求必须在两入口得到一致的安全结果。

经营问答网页路径为 `/lanqi/business-qa`：服务端先确认兰琪产品权限与租户，再只装配经营档案的 `confirmedFacts`，固定调用 `beauty_business_qa -> general_qa@0.2.0`。问题少于 2 个字在运行和积分前拒绝；受控模式只保存明确标识的流程预览且积分为 0；真实模式沿用平台 AgentRun、幂等与账本合同。

“兰琪小红书图文生成”是一个用户任务：一次输入 → 页面展示整包报价 → 用户点击唯一主按钮确认 → 标题/正文/标签与承接 → 内部专业图片提示词/负向提示词 → 同一 `packageId/quoteId/requestId` 生图、结算、选择、保存、复制文字和下载图片。提示词只在高级详情中可查看调整，主路径不要求用户理解或复制提示词；文案失败不建图片，图片失败保留文案并允许只重试图片。

LQ-14 将最后一步实现为同页异步任务：报价 → 显式确认 → 排队/处理中 → 成功落库或明确失败 → 选择/保存/重新生成；取消、超时、提交失败和落库失败走单次退款。默认 `disabled`，本地可用不计费 `mock` 验收；真实模式必须由总调度单独批准预算后启用。

小红书策略/文案和兰琪知识综合保持 `deepseek-v4-pro + reasoning_high/deep`。专业图片提示词仍使用 `deepseek-v4-pro`，但经过同套 8×3 Eval 后采用有界 `reasoning_standard`、`thinking=disabled`、`max_tokens=4096` 与严格 JSON Output。`qwen3.8-flash` 已接成默认关闭的兰琪低风险候选：只有低风险分类、标签或格式转换在“显式启用 + 同套 Eval 批准”同时成立时才可选择，且强制非思考、最多 2048 输出 tokens；专业任务永远回到 Pro。文本模型不生成图片，图片由百炼媒体 adapter 异步执行；任何降级结果必须标为受控草稿。
