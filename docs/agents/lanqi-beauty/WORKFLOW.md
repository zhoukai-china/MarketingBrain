# 蓝旗智能体开发流程

## 开发顺序

蓝旗当前先做产品和知识基础，不能直接从页面按钮开做。

```text
LQ-01 授权契约
→ LQ-02 知识结构与版本
→ LQ-03 租户、推荐与开通
→ LQ-04 门店经营档案
→ LQ-05 经营诊断
→ LQ-06 项目、获客与成交
→ LQ-07 算力钱包与复盘
```

每个编号是一个可以独立验收的结果。一个任务完成输入契约、服务逻辑、页面路径、失败处理和回归测试，不再把同一结果拆成“做按钮”“接接口”“再手测”三个互相脱节的任务。

## 每个任务的固定闭环

1. 从 `tasks/` 中建立任务卡，写清用户结果和不应发生的结果。
2. 读取当前授权规则、知识版本、产品契约和相关源码。
3. 建立正常、缺资料、无权限、跨租户、工具失败和重复请求样例。
4. 保存 Champion 基线；Bug 任务先证明新增回归会失败。
5. 一次只改变一个主要变量，实施最小改动。
6. 运行蓝旗专项检查、`qa:fast` 和与风险匹配的回归。
7. 页面任务必须真实操作桌面和移动核心路径。
8. 更新任务卡和 `STATUS.md`，留下下一任务可直接读取的交接证据。

## 知识上线流程

```text
蓝旗提供资料
→ 确认所有权、授权范围和有效期
→ 去除客户隐私与无权内容
→ 结构化并标注来源/版本/适用条件
→ 建立检索与拒答 Eval
→ 蓝旗业务负责人复核
→ 测试租户灰度
→ 批准后激活
```

每日学习或用户反馈只能生成脱敏样例、评分、聚类和改进候选，不能自动修改或激活生产知识、Prompt、Skill、路由和代码。
