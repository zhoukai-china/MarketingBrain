# 兰琪智能体业务契约

## 输入契约

- 当前租户、用户、角色和兰琪授权必须由服务端可信身份确定，不能采用模型生成或前端自报值。
- 门店档案至少区分已确认事实、用户估计、知识推断和待补资料。
- 使用内部定价时必须确定知识版本、适用区域、项目、门店类型和生效时间；资料不足时先追问或给出待确认项。

## 输出契约

- 经营结论必须说明依据、适用条件、优先级和下一步动作。
- 项目与内部定价建议必须携带兰琪知识版本；版本过期或无权限时拒绝展示。
- 不能编造门店业绩、兰琪案例、价格、效果、授权关系或已经执行的动作。
- 关键字段缺失时明确标记“待补”，不能用行业常识伪装成门店事实。

## 权限契约

- 兰琪授权核心方法：仅向有效授权范围内的租户开放。
- 兰琪总部管理资料：只供总部角色使用，不因“使用同一智能体”向加盟商或外部门店开放。
- 门店私有资料：只属于该门店租户；推荐方、其他加盟商和其他门店不可读取。
- 任务临时资料：只用于本次授权会话，按平台数据规则到期清理。
- 推荐关系不等于数据访问权。

## 算力与外部动作契约

- 每次计费都要有租户、运行、金额、状态和幂等键，失败或取消按实际消耗规则处理。
- 同一请求重试不得重复扣费。
- 内容发布、客户消息、广告投放、付款和真实业务配置默认只生成草稿或预览；按外部动作授权流程确认后才执行。

## 媒体预览契约

- LQ-10 零付费阶段只创建租户内提示词预览，不创建媒体任务、不预留或扣减积分、不调用外部图片模型。
- 文生图输入必须包括画面需求、用途、比例、视觉方向、文字方式和权利确认；缺少权利确认或涉及未授权真人冒充时拒绝。
- 文生图增强结果必须拆分为可编辑意图理解、仅影响成图的待补问题、2–3 个差异明确的视觉方向、正向提示词、负向提示词、后期中文叠字、视觉参数、知识/事实边界和供应商无关 adapter；不得用规则清单冒充绘图提示词。
- 正向提示词只包含主体、构图、场景、光线、色彩、镜头、材质与清晰度等可视语言；费用、权限、计费、审核、系统说明和事实校验属于独立执行边界，禁止混入绘图提示词。
- 安全规则必须区分主动冒充/换脸请求和“禁止冒充、不要模仿”等用户否定约束；前者 fail closed，后者应被保留为安全限制。
- 每条预览保存 enhancer 版本、脱敏输入摘要、最终 prompt、negative prompt、参数和用户所选方向；不保存密钥或未脱敏客户原始资料。
- 提示词只能注入门店档案中的已确认事实；无激活兰琪知识版本时必须标记 `not_loaded`，不能用通用知识冒充兰琪方法论。
- 对外只声明供应商无关 capability `media.image.generate`；供应商、模型、API 密钥、内部成本和回调参数不进入用户结果。
- 真实生成前必须同时满足预算确认、账号模型权限、永久对象存储、幂等计费与失败结算；任一缺失即 fail closed。
- 同页“确认并生成图片”只有在 `media.image.generate`、`media.asset.persist`、预算授权和 `credits.reserve_and_settle` 同时就绪后才可启用；零付费阶段必须禁用且不得调用媒体任务接口。

## 图片生成任务契约

- 报价只返回用户可见积分、是否计费、执行模式与阻塞原因，不创建任务、不扣费，也不暴露供应商、模型、密钥、内部成本或临时结果 URL。
- 图片任务必须绑定当前租户、用户、LQ-10 `previewId`、最终正向/负向提示词、比例、结构参数、实际 Provider/model、prompt 版本和唯一幂等键；同键同输入恢复原任务，同键变更拒绝。服务端必须恢复本租户预览并核对关键字段，禁止信任客户端替换后的 prompt 或版本。
- 真实模式默认关闭；只有真实执行批准、模型能力、租户持久存储和积分结算同时就绪才允许确认。演示租户永不创建付费任务。
- 成功仅在供应商结果已下载到租户资产区后成立；供应商临时 URL 不作为交付。成功结算与取消/退款必须条件互斥，失败、取消、超时或落库失败只退款一次。
- 任务支持排队、处理中、成功、失败、取消；刷新可恢复；只有供应商仍为 `PENDING` 才尝试取消。成功资产可选择、保存和租户内恢复。
- 租户 A 不能列出、刷新、取消、选择、保存或下载租户 B 的任务/资产。文件按租户哈希目录归属，元数据再次校验租户与任务。
- `mock` 仅限非生产 E2E，明确标注不代表真实画质，不调用文本/图片外部模型、不扣积分；生产环境 fail closed。

## 兰琪运行时模型与推理契约

- 兰琪知识综合、小红书策略与文案固定使用 `deepseek-v4-pro` 与 `reasoning_high/deep`。
- 专业文生图提示词与多轮视觉修改仍固定使用 `deepseek-v4-pro`，但采用有界 `reasoning_standard`、`thinking=disabled`、`max_tokens=4096` 和 `response_format=json_object`；本地 Agent、远程 MCP 和审计记录必须一致。结构不合格时 fail closed 或明确受控草稿，不静默重试。
- `deepseek-v4-flash` 与 `qwen3.8-flash` 只允许承担低风险分类、标签、格式转换或候选初筛，且必须同时显式启用并通过兰琪同套 Eval；未批准时继续使用 Pro，禁止自动降级。Qwen 候选固定阿里云百炼国内兼容接口、`thinking=disabled`、`preserve_thinking=false`、`reasoning_standard` 和最多 2048 输出 tokens；它不属于高能力模型白名单，不能承担知识综合、小红书策略/文案、专业图片提示词或视觉修改。
- 专业模型超时、结构不合格或模拟环境只能返回明确标识的“受控草稿（专业模型未完成）”，不能宣称完成专业增强。
- DeepSeek 只负责结构化提示词生成与事实/授权复核，不生成图片；图片由已批准的 `media.image.generate` adapter 执行。模型与 Provider 可内部审计，但不向普通用户暴露供应商、密钥或内部成本。

## 美业经营问答契约

- 固定链路为 `beauty_business_qa -> agent_beauty_acquisition -> general_qa@0.2.0`；请求体不得指定或切换 brand、tenant、capability、Skill 或版本。
- 最小必填只有经营问题，去空白后至少 2 个字、最多 1200 字；经营档案不是提交前硬前置。缺少档案时可给通用起步动作，但必须明确最关键待补资料。
- 上下文只使用当前租户经营档案的 `confirmedFacts`；`estimatedFacts`、`needsInput` 与其他租户资料不得升级成已确认事实。未知价格、疗效、顾客案例、业绩和已执行动作禁止补造。
- 正式回答固定包含“先给结论、今天先做、可以直接使用、仍需确认”；结构或事实门禁失败不保存成功记录、不扣积分。
- 同一租户、同一 request key、同一输入只产生一个结果；同 key 不同输入返回冲突。会话、消息和 AgentRun 按租户隔离，跨租户读取返回 404。
- controlled mock 仅验证页面、固定路由、历史和失败语义，显著标识不代表真实智能回答质量；外部 Provider 与积分均为 0。

## 双入口鉴权与计费契约（网页与 WorkBuddy 共用执行层已实现）

- 独立网页与 WorkBuddy MCP 共享同一兰琪 capability、租户资料、会话历史、`CreditAccount` 和 usage ledger；任一入口创建的授权内记录可由另一入口恢复。
- Web 入口按可信会话校验 `lanqi` entitlement，WorkBuddy 入口按凭据绑定的 `beauty-industry` entitlement 校验；两者只能进入固定 `operations:business-qa / beauty_business_qa / general_qa@0.2.0`，不得从请求参数切换产品、租户、Skill 或版本。
- MCP 凭据只保存哈希，绑定兰琪 product/tenant/user/role/entitlement，支持过期、撤销、轮换、限流、幂等、审计和最后使用时间；请求参数不能自行指定 tenant/user/store 绕过令牌。
- 余额不足时两入口都必须在 Provider 调用前拒绝并引导到兰琪品牌充值页。小红书图文真实生图沿用预留 → 明确确认 → 结算/失败释放；文本问答按底层统一规则扣费。商业价格未确认前不实现充值或生产计费。

## 小红书图文作品契约

- `/lanqi/content-studio` 是用户唯一的小红书图文入口；`/lanqi/image-studio` 仅保留兼容和内部调试，不进入用户主导航。
- 页面以一个主按钮确认按钮旁已展示的整包报价；同一 `packageId/quoteId/requestId` 依次关联文案草稿、图片提示词预览、媒体任务和租户资产，重复点击或刷新只能恢复同一作品。
- 统一结果包含 3 个标题候选与选中标题、完整正文、标签、互动承接、事实/合规边界、真实或明确标识的 mock 图片、实际积分和保存时间。图片提示词仅在高级详情展示。
- 素材权利和人物授权是图片阶段硬前置；未确认时主按钮真实 `disabled`/`aria-disabled` 并说明原因，不能只用样式伪装不可用。
- 文案超时、取消、结构不合格或 Provider fallback 必须 fail closed，禁止固定模板或其他任务内容冒充小红书文案；文案失败不得创建图片任务。
- 图片失败时作品进入部分成功，保留并可复制文案；只重试图片不得重新调用或重复计费文案。余额不足、取消、网络错误和 API 拒绝都有明确终态。
- 用户侧图片通过租户鉴权端点读取和下载；页面用授权响应生成 Blob 预览，下载响应的文件名、Content-Type 与扩展名必须正确，不暴露 Provider 临时 URL、服务器绝对路径或其他租户资产。

## 硬失败

以下任意一项发生即判定失败，不能被其他评分抵消：跨租户泄露、总部私密知识越权、内部定价编造、无授权使用兰琪知识、重复扣费、伪造已执行动作、把门店原始数据写入全局知识。
