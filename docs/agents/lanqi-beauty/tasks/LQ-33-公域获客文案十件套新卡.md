## 验收条件

1. 正常路径：填够行业 / 卖点 / 目标人群 → 出十节齐全的 Markdown（结构校验通过），页面可复制、可导出。
2. 失败路径：信息不足 → 返回「【需补充信息】」并说明缺什么；模型失败 → 明确报错且不扣积分。
3. 不应发生：编造门店事实 / 数据 / 客户名；跨租户读取；与平台文案智能体产出不一致（同一输入下结构规则一致）。
4. 可观测结果事件：`lanqi` 侧生成记录（租户、输入摘要哈希、章节齐全性、扣费与幂等键）。

## 基线与失败证据

### 真实 Eval 证据（`pnpm.cmd lanqi:copy-kit-live-eval`，真实模型，同一样例 3 次）

| 运行 | 配置 | 结果 | 关键数据 |
|---|---|---|---|
| 第 1 轮 | `maxTokens 8192` + 默认推理档 | **2 passed / 1 failed** | 失败那次 `finishReason=length`、`completionTokens=8192`（推理吃掉 6494）→ `deepseek_provider_output_token_limit`；成功两次正文 3.5k 字、结构合格、无样板门店泄漏 |
| 第 2 轮 | `maxTokens 8192` + `thinking=disabled` | **0 passed / 3 failed** | 正文掉到 ~2.5k 字，出现「文案区含违规引导词」 |
| 第 3 轮 | `maxTokens 16384` + 默认推理档 | **1 passed / 2 failed** | 失败 ①「口播稿过短（133 字 < 150）」；失败 ②「文案区含违规引导词」——触发文本是表格里的合规备注（`不出现私信类引导`），属**校验器误伤合规说明句** |
| 修复后（定版） | `maxTokens 16384` + 默认推理档 + 提问壳四条硬要求 | **15 passed / 0 failed（3/3 全绿）** | 三次 `finishReason=stop`，正文 3.1k–3.3k 字；十节齐全；与共享合同校验逐条一致；无样板门店 / 他人信息泄漏 |

**修复动作（最小改动，不改共享合同与校验器）**：
1. `copy-kit-service.ts` 默认输出额度 8192 → **16384**（provider 实测接受），另留 `LANQI_COPY_KIT_MAX_TOKENS` 可调；截断类失败消失。
2. 兰琪提问壳补四条硬要求：口播正文 ≥150 汉字且每句 ≤40 字；第七节正好 3 行标题且话题逐字写「大流量 / 精准 / 行业」；获客型第三节 5-6 组【问·…】、第十节主投本地推；全文任何位置（含禁忌说明与表格备注）不得出现被禁词字面。
3. **不改共享校验器**：改它会同时改货架「文案智能体」的行为，属另一条回归线，不在本任务范围。

## 遗留问题（需老板拍板 / 单独立项）

- **独立计费单价**：当前默认 **40 积分 / 次**（与货架「文案智能体」同合同同档价），可用 env `LANQI_COPY_KIT_CREDITS` 覆盖；老板拍板后只改配置即可。
- **积分账户口径**：兰琪所有能力（含本卡）扣的是**租户积分账户 `creditAccount`**，而 `/recharge` 钱包页充的是**用户钱包 `wallet`**（`sitong-wallet.ts`）。两条账本目前没有同步代码。老板若在兰琪充值后仍提示「积分不足」，需要单独立项把「兰琪充值 → 租户额度」打通——本卡按现状与兰琪其它能力保持一致，未擅自改账本。
- **偶发结构失败的最优解**：真实生成仍是非确定性的，当前失败一律不扣积分并可重试；若后续要把偶发率继续压下去，应做「有界修复重写一次」的独立任务（多一次内部调用，不额外扣用户积分），而不是继续加长提问壳。
