## 本次范围（待用户确认入口形态后细化）

- 用户已选：**新增一张卡**（不是塞进现有「文案改稿」页做模式切换），并要有清晰、独立的计费口径。
- 复用**同一份正式 Skill 合同**（`内容十件套 V5` 提示词 + 结构校验 `parseCopyTen`），办法是把合同抽到共享模块（例如 `apps/api/src/products/beauty-industry/content-ten-contract.ts`），由 marketplace 与兰琪两侧共同引用——**不复制第二份提示词**。
- 兰琪侧路由与页面独立：租户隔离、失败关闭（缺关键信息时回「【需补充信息】」而不是编造）、结果可复制 / 导出。
- 计费：独立于「文案改稿」与视频侧口径，单价待老板拍板（建议按次固定积分，成本＝一次 Pro 文本调用）。

## 本次不做

- 不改 marketplace 现有文案智能体的对外文案与售价。
- 不做图片 / 视频侧联动（十件套只出文案与脚本）。

## 验收条件

1. 正常路径：填够行业 / 卖点 / 目标人群 → 出十节齐全的 Markdown（结构校验通过），页面可复制、可导出。
2. 失败路径：信息不足 → 返回「【需补充信息】」并说明缺什么；模型失败 → 明确报错且不扣积分。
3. 不应发生：编造门店事实 / 数据 / 客户名；跨租户读取；与平台文案智能体产出不一致（同一输入下结构规则一致）。
4. 可观测结果事件：`lanqi` 侧生成记录（租户、输入摘要哈希、章节齐全性、扣费与幂等键）。
