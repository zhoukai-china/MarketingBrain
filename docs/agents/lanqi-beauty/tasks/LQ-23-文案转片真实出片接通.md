## 本次范围

- `apps/api/src/services/lanqi-media-staging.ts`（新建）：门店上传的「首帧图」先落到**本平台自己的存储**（`UPLOAD_DIR/lanqi-media/staging/<sha256(tenantId) 前 24 位>/lanqi-ff-…`），再签发一条**限时 + 绑定租户指纹**的 HMAC-SHA256 外链交给视频模型抓取；缺公网基址或缺签名密钥一律 fail closed。公开读路由 `GET /lanqi/media/first-frame/:id` 只校验签名，不挂租户 entitlement；改 `e=`、过期、换租户指纹一律 404。
- `apps/api/src/services/lanqi-media-generation.ts`：`image_to_video` 下发 `input.img_url` + `parameters:{resolution, duration, audio:false, prompt_extend:false, watermark}`（**无声必须显式 `audio:false` 且不下发 audio_url**）；时长由固定 5/10 放开为整数 `[2,15]`；图生视频不再强制 `ratio`（比例由首帧图决定）；新增 `isSameLanqiMediaRequest()` 统一幂等指纹；新增 `LANQI_MEDIA_IMAGE_REAL_EXECUTION_APPROVED`，**图片与视频分开放行**，本轮只放行图生视频，付费生图仍关闭。
- `apps/api/src/services/lanqi-media-assets.ts`：新增 `persistLanqiProviderVideo()`（上限 120MB、只认 `video/mp4`、校验 MP4 `ftyp` 魔数，失败码 `media_asset_invalid_container`）。
- `apps/api/src/routes/lanqi-media-generation.ts`：`firstFrameId` / `firstFrame`（base64）两种首帧图传法；`GET /lanqi/media/jobs?kind=image_to_video` 只在视频页显式请求时返回视频任务（旧工作台默认仍只看 `image`）；成片下载按 `video/mp4` 给出 `lanqi-video-*.mp4`；只有「Provider 已出结果但结果不能安全落盘」才退款，网络抖动仍按可重试处理。
- `apps/web/src/pages/LanqiAcquireVideoPage.tsx`：第 3 步上传的首帧图在**浏览器侧**把最长边压到 1280 再转 base64 JPEG；新增逐镜出片状态机（`queued/running/succeeded/failed`）、轮询（6s × 80 次）、逐镜失败提示与重试、成片下载；未选老板正面照时明确拦下，**不静默降级成文生视频**。
- `apps/web/src/main.tsx`：在 `/lanqi/acquire` 总闸**之前**插入 `/lanqi/acquire/video` 分支，让视频页在「只放私域营销」的上线收口下仍可直达。
- `apps/api/src/config/env.ts`：新增上表的 5 个 `LANQI_MEDIA_*` 变量；`ALIYUN_VIDEO_REPLICATION_MODEL` 默认值由旧名 `wan-animate-mix` 改为 **`wan2.2-animate-mix`**（旧名会被服务端拒绝）。
- 回归脚本：`scripts/lanqi-media-staging-smoke.ts`（新建，进 `qa:lanqi-foundation`）、`scripts/lanqi-media-generation-smoke.ts`（扩写）。

## 验收条件

1. 正常路径：门店走完四步并确认生成 → 每镜创建 1 个 `image_to_video` 任务 → 30 积分/秒 × 3 秒 = 90 积分/镜 → 终态 `succeeded` 且成片落本租户资产区、可播放可下载。
2. 失败路径：未选老板正面照 → 页面明确拦下、不发请求、不扣积分；首帧图签名过期 / 换租户指纹 / 篡改 `e=` → 404；Provider 报错或超时 → 任务 `failed` + 积分原路退回；结果下载失败或格式不是 MP4 → 502 且退款。
3. 不应发生：跨租户读到别人的首帧图或成片；未授权肖像也能生成；失败仍显示「已出片」；同一 `requestKey` 重复确认二次扣费或新建任务；绕过授权门禁直连 Provider 下单。
4. 可观测结果事件：响应 `creditCost` / `status` / `idempotent`；任务表 `kind=image_to_video`、`providerTaskId`、`parameters.firstFrameId`；资产 `metadata.contentType=video/mp4`。

## 基线与失败证据

- 基线命令：`pnpm.cmd lanqi:media-staging-smoke`、`pnpm.cmd lanqi:media-generation-smoke`、`pnpm.cmd content-system:viral-replication-smoke`。
- 修复前失败测试/Eval：首帧图没有稳定暂存 ID 时，幂等指纹会被迫用「每次签名都变的整条外链」→ 同一 `requestKey` 会被判成新请求（红灯覆盖在 `lanqi:media-staging-smoke` 的 9 组用例里）；时长被限制为 `5|10` 导致 3 秒/镜无法下发；`persistLanqiProviderImage()` 只认图片容器，MP4 落盘会被判非法。
- 现象、根因和连带影响：根因是**视频与图片共用同一套「按次」假设**（固定时长、图片容器校验、把签名 URL 当稳定指纹），连带影响是「要么下不了单、要么重复扣费、要么成片存不下来」。改为「按秒计价 + 稳定暂存 ID 做指纹 + 图片/视频分容器校验 + 图片与视频分开放行」。
