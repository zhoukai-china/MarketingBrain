# LQ-29 兰琪爆款复刻：参考素材三条现场缺陷（抖音分享口令识别 / 已传素材删除替换 / 出片主按钮点不了）

状态：已修 + 已上测试实例与生产（2026-09-14；**出片链路的权益口径留一项待老板拍板，见「阻塞项」**）

## 归属与口径

- 产品：兰琪（`docs/agents/lanqi-beauty/`），公域获客 → 视频获客 → 爆款复刻。
- 变更层级：产品专用（页面交互 + 前端错误口径）。**未改后端路由、未改鉴权、未改计费。**
- 用户口径（2026-09-14「兰琪-公域获客-页面开发」任务，附 3 张现场截图）：
  1. **没有正确识别抖音链接**——粘贴抖音「分享 → 复制链接」得到的分享口令，被页面判成「这不像一条完整链接」；
  2. **已上传的照片 / 视频无法删除、无法替换**；
  3. **「先报价，再出片」点不了**。

## 根因（先复现、后定位）

| # | 现象 | 根因 | 定性 |
|---|---|---|---|
| ① | 分享口令被判成「这不像一条完整链接」 | `parseReferenceLink()` 把**整段粘贴文本**直接丢给 `new URL()`。抖音 App 的「复制链接」复制的是**口令文本**（`7.32 复制打开抖音，看看【…的作品】https://v.douyin.com/xxxx/ 复制此链接，打开抖音搜索…`），不是裸 URL → `URL` 构造必然抛错 → 真实口令一律落到 catch 分支 | 真缺陷（P1，正常路径被挡） |
| ② | 已上传素材删不掉、换不掉 | 上传区只有 `FilePick`，**已上传后没有任何删除入口**；`uploadAsset()` 只处理「再选一次」，页面也没有清掉上一次报价 / 任务 / 成片的路径 | 真缺陷（P1，用户无法反悔重来） |
| ③ | 「先报价，再出片」点不动 | 主按钮 `disabled={busy \|\| !quote?.canConfirm}`——**拿到报价之前恒为禁用**，而它旁边的「看报价」是 `ghost` 次级按钮，用户看不出主按钮为什么点不动，也拿不到任何解释 | 真缺陷（P1，主路径无出口） |

### ③ 的第二层（不是本条缺陷的根因，但决定用户能否真的出片）

前端放开按钮后，`POST /viral-video-replication/quote` 在生产对**只有兰琪权益**的账号必然返回 **403 `product_access_denied`**：

- 该路由在 `apps/api/src/products/register.ts` 里**注册在兰琪产品 entitlement 作用域之外**（注释写明「只用签名校验」），但 `apps/api/src/routes/viral-video-replication.ts` 的 `context()` 内部硬编码只认 `productCode: "beauty-industry"` 的 active 权益（且要求 `source === "database"`）。
- 生产库只读实测（2026-09-14）：active 权益 `takeaway=190 / founder-ip=190 / lanqi=9 / beauty-industry=7`；**9 个兰琪租户里只有 2 个同时持 `beauty-industry`**，且这 2 个都是 2026-08-24 的历史租户；2026-09-13~14 新建的「兰琪」租户（含老板在用的号）**只有 `lanqi`**。→ 老板一点就走 403。
- 后端把 403 统一回成「当前步骤未完成；请按前置条件处理」，会把人引到「素材没填对」的错误方向。**本轮只把这句话说准**（照实告诉用户「账号还没开通这项出片能力、与素材无关」），**没有动鉴权**——放宽谁能付费出片属权限 / 计费口径变更，见文末阻塞项。

## 本次范围

- `apps/web/src/pages/LanqiAcquireVideoPage.tsx`

## 验收条件

1. 正常路径：粘贴抖音分享口令（文字 + 短链 + 中文提示混排）→ **识别成功**并登记为参考来源，且**不发任何请求、不出片**。
2. 正常路径：上传原片 / 照片后**能删除**，删除后能重新上传；删除会清掉上一次报价与任务，重传后是全新一次请求。
3. 正常路径：素材与授权齐了但还没报价时，主按钮**可点**，点击先走报价；报价可确认后按钮变「✅ 确认并出片（按报价扣 N 积分）」；**点击这一下才建任务、扣积分**。
4. 失败路径：整段没有任何链接 → 明说「没有链接」并给「分享 → 复制链接」步骤；非抖音链接 → 报出实际域名；素材没齐 → 主按钮禁用并点名「还差：…」；服务端 403 → 照实说「账号未开通出片能力，与素材无关」，不扣积分。
5. 不应发生：不出现「这不像一条完整链接」这类把真实口令判死的提示；未确认前不创建任务、不扣积分；页面不出现模型 / 厂商名；不跨租户串数据。
6. 可观测结果事件：`data-lq-vd-primary` 状态迁移 `missing → need_quote → ready`；`data-lq-vd-remove` 出现 / 消失；报价请求只在用户点击后发生。

## 阻塞项（需老板拍板，属权限 / 计费口径变更，Agent 不擅自执行）

1. **给在用的兰琪租户补 `beauty-industry` 权益**（只改数据，不改代码）；或
2. **改后端鉴权口径**：让 `/viral-video-replication/*` 接受 `lanqi` 权益（要改 `apps/api/src/routes/viral-video-replication.ts` 的 `context()`；该路由是公共路由，涉及权限与计费，风险更高，需完整回归）。

另有事实待确认：生产上持 `lanqi` 权益的租户与历史上传素材的租户不是同一个（老板可能换过微信号 / 租户），需要老板确认**哪个租户是在用的**，再决定给谁开通。
