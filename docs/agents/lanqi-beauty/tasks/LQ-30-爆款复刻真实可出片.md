# LQ-30 兰琪爆款复刻：让门店账号真能出片（兰琪权益 / 素材授权声明 / 单批许可自动签发）

状态：开发中（用户 2026-09-14「按推荐做」：A 自动许可 + 在线勾选即算声明 + 给在用的兰琪租户补权益）

## 归属

- 产品：兰琪（`docs/agents/lanqi-beauty/`），公域获客 → 视频获客 → 爆款复刻。
- 层级：产品任务含公共平台子改动（`/viral-video-replication/*` 是美业与兰琪共用的出片能力）。
- 风险：高（涉及权限边界与付费执行）。
- 预计修改热点：`apps/api/src/services/video-replication-entitlement.ts`（新）、`apps/api/src/routes/viral-video-replication.ts`、`apps/api/src/services/beauty-video-{asset-authorization,execution-permit,controlled-execution}.ts`、`apps/api/src/config/env.ts`、`apps/web/src/pages/LanqiAcquireVideoPage.tsx`。
- 是否允许并行：否（本轮独占出片链路热点）。

## 用户结果

兰琪门店账号上传原片 + 人像、勾选四项授权后，能在同一页拿到报价并确认出片，成片可播放/下载；未开通权益、时长超预算或积分不足时必须明确说明原因，且不扣积分。

## 本次范围

- 出片链路（`/viral-video-replication/*`）接受 `lanqi` 权益：路由准入、素材授权 scope、许可 currentAccess 三处统一走产品权益清单。
- 页面在报价前提交**素材授权声明**（参考原片 + 人像），依据 = 用户在线勾选生成的声明文本（不再要求门店上传 PDF）。
- 单批执行许可：新增 `VIDEO_REPLICATION_PERMIT_MODE`（`operator` 默认 / `auto`）；`auto` 下服务端按既有预算上限自动签发一条绑定本次请求的许可，仍受单条成本上限、输出时长上限、积分余额与幂等约束。
- 报价缺口口径：积分不足、时长超预算等以人话展示，不建任务、不扣积分。

## 本次不做

- 不放宽成本上限（仍为生产 env 的 `ALIYUN_VIDEO_REPLICATION_MAX_COST_FEN`）；不自动充值、不发体验积分。
- 不改一键成片（用户 2026-09-14 明确「先不用管一键成片」）。
- 不改定价（24 积分/秒已拍板）；不改美业侧既有页面。

## 验收条件

1. 正常路径：只有 `lanqi` active 权益的租户调用报价 → 不再 403；素材授权声明齐备 + `auto` 模式下报价返回 `canConfirm=true` 与积分；确认后建任务、扣积分。
2. 正常路径：页面粘贴抖音分享口令仍只登记来源；上传/更换/删除素材仍可用（LQ-29 契约不回退）。
3. 失败路径：没有 `beauty-industry`/`lanqi` 任一 active 权益 → 仍然 403 `product_access_denied`；时长超出单条预算 → 报价缺口 `provider_budget_exceeded`；积分不足 → 缺口 `insufficient_credits`，均不建任务、不扣积分。
4. 不应发生：`operator` 模式下无许可 → 422 `execution_permit_required`（既有行为不回退）；跨租户素材/任务不可见；不出现模型或厂商名；不编造报价。
5. 可观测结果事件：报价响应 `canConfirm`/`gaps`；`BeautyVideoExecutionPermit` 行按 `(tenantId,userId,requestKey)` 唯一；任务 `billingStatus` 从 `reserved` 到终态。

## 基线与失败证据

- 基线命令：`pnpm.cmd beauty-industry:video-execution-smoke`、`pnpm.cmd lanqi:acquire-instance-acceptance`。
- 修复前失败测试：测试实例真实浏览器 41 项 / 失败 2 项，两条都指向 `POST /viral-video-replication/quote` 403（QA-20260914-004）。
- 根因：出片链路三处硬编码 `beauty-industry` 权益；页面从未提交素材授权声明；许可只能由运营离线签发。
