## 用户结果

门店老板在「一键成片」第 4 步上传一段音频（或一段带声音的视频，由平台抽取其声音），逐镜出片后点一次「合成成片」，即可拿到**一条按分镜顺序拼接、带这段声音的成片**并可播放 / 下载。

## 本次范围

- 音频卡真实上传：`音频卡` 由「占位记录」改为可上传（`audio/*` 或带声音的 `video/*`，≤20MB），上传走既有 `POST /files`，得到 `fileId`；上传视频时平台用 ffmpeg **抽取其音轨**作为音轨。
- 一次成片只用一条音轨：音频卡里可上传多段，但用户必须显式指定「本片音轨」；未指定时取第一条已上传的。
- 音频授权：只要带了音轨，必须先勾选「我拥有这段音频 / 视频的使用权或已获授权」，未勾选不创建合成、不扣积分。
- 合片：所有镜次出片成功后，提供「合成成片」入口；后端按分镜顺序拼接（统一画布、统一帧率）并混入音轨，输出一条 MP4。
- 逐镜下载保留：合成不替换原有「下载这一镜」。
- 计费：合片是本地 ffmpeg 计算，**不额外扣积分**；页面明确写出这一点。

## 本次不做

- 不做自动配音（TTS）、不做多音轨混音 / 音量包络编辑、不做字幕烧制。
- 不改逐镜出片与计费口径（`/lanqi/media/quote|confirm|jobs/*/refresh` 与积分单价不变）。
- 不打开「门店素材成片 / AI 剪辑」（`VIDEO_RENDERING_READY=false` 保持 fail-closed）。

## 验收条件

1. 正常路径：上传一段 ≤20MB 音频 → 勾选音频授权 → 逐镜出片全部成功 → 点「合成成片」→ 拿到 1 条 MP4，时长 ≈ 各镜之和（±1s），可播放与下载，音轨非空（`ffprobe` 有 audio stream）。
2. 正常路径（视频抽音）：上传一段带声音的 `MP4` 作为音轨 → 合成成功，成片含音频流。
3. 失败路径：未勾选音频授权 → 后端 400 `audio_rights_required`，不创建合成、不扣积分；音轨文件不属于本租户 → 404 `audio_file_not_found`；镜次未全部成功 → 409 `shots_not_ready`；镜次不属于本租户 → 404 `shot_not_found`；ffmpeg 不可用 → 503 `compose_tool_unavailable`（明确报错，不返回无声成片冒充成功）。
4. 不应发生：跨租户读取他人镜次 / 音轨 / 成片；重复点「合成成片」重复扣积分或产出多条不同成片（同 `requestKey` 幂等复用）；音频缺失时静默成功。
5. 可观测结果事件：`compose` 记录（`tenantId` / `shotJobIds` / `audioFileId` / `composedAt` / `durationSeconds` / `bytes`）与接口返回的 `audioIncluded` 布尔值。

## 基线与失败证据

- 基线命令：`pnpm.cmd lanqi:acquire-ui-contract-smoke`、`pnpm.cmd lanqi:video-copy-smoke`
- 修复前失败测试/Eval：`scripts/lanqi-media-compose-smoke.ts` 与 `lanqi-acquire-ui-contract-smoke` 新增段（实现前全红）
- 现象、根因和连带影响：音频卡 `FilePick` 被 `disabled` 写死、后端无任何合片能力；视频模型 `wan2.6-i2v-flash` 只出**无声**视频（`parameters.audio=false`），且成片只按镜交付、无拼接，所以「上传音频就能有声音」在现状下无法实现。
