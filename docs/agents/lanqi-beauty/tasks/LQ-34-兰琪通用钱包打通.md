# LQ-34 兰琪通用钱包打通（充值入口在兰琪、钱包与思潼 AI 通用）

状态：**①②③④⑤ 已切完 + 测试实例灰度通过（真实 HTTP + 真实库 38/0）；生产未发布——待老板确认迁移 dry-run 报告后再走发布流程**

## 用户口径（2026-09-16 老板拍板，逐条可追溯）

1. 「**兰琪的用户只使用兰琪智能体**，也就是说需要在兰琪智能体里充值；未来在兰琪智能体里加一个『更多智能体』的接口，点击之后进入思潼 AI，用户可以继续在思潼 AI 里使用其他智能体。**在兰琪智能体充值的积分，可以支持同时在思潼 AI 里使用其他智能体**。也就是说钱包是通用的。未来用户进入思潼 AI 之后，也可以在思潼 AI 充值。」
2. 多人门店的付费主体：**选选项 1** —— 「兰琪里不管谁操作，都扣**租户老板（owner）的钱包**，流水里记『谁操作的、扣的是老板的钱』；思潼 AI 侧保持『谁登录扣谁的钱包』。」
3. 迁移方式：**选 Phase 2（正式，不做双轨过渡）** —— 「把历史租户额度一次性迁进钱包（或按门店发一笔等额），下线回退分支，只留一本账；补对账报表和退款一致性。」
4. 「**不显示人民币消耗**，兰琪的积分计费逻辑和思潼 AI 保持一致。」

## 实施计划（按顺序，每步都有验证）

### 1. 计费主体解析（已完成）

- 新增 `apps/api/src/services/lanqi-wallet.ts`：按 `tenantId` 解析**租户 owner**，命中失败即 **fail closed**（`lanqi_wallet_owner_missing`，不扣费、不放行）。

- 幂等与审计口径：
  - 幂等键统一为 `lanqi:{tenantId}:{requestId}`，避免不同门店共用同一 owner 时撞键；

  - 操作人写进 `WalletLedger.source`（`lanqi:operator=<userId>`），付费人是 owner，二者分开可审计。

#### 已踩过的坑（避免重复）

- 钱包幂等键是 `(walletId, refRequestId, type)`：兰琪侧统一用 `lanqiWalletRequestId(tenantId, requestId)` 加租户前缀，否则同一 owner 服务多门店时会撞键。
- `refundWalletCredits` 要求 `breakdown: {paid, bonus}`；**不要自己记账**，用 `refundLanqiWallet`（它读原 consume 流水按桶退回）。
- `lanqi-wallet-smoke` 是库级回归，会建临时租户/用户/钱包并自动清理；本机 `.env` 指向 `localhost/sitong_os_v2`（dev 库），**不要**把它指向生产跑。

#### ③④⑤ 复核结论（2026-09-16 读源码后补，下次直接照做）

这三处不是"扣一笔钱"，而是**预留-结算模型**，必须一起重构、一起回归：

- ⑤ `beauty-video-execution-permit.ts`：`claim()` 在 `atomic(tx => …)` 里读 `tx.creditAccount.balance` 跟 `a.creditCost` 比。改法：把余额读提前到 `atomic` 之外（`readLanqiWalletBalance(a.tenantId)`），原子块里只做比较；找不到 owner → 直接 `reject("insufficient_credits", 402)`（fail closed）。
- ④ `beauty-seedance-execution.ts` 的 `submit` 分支：**同一个事务**里做了四件事——条件扣减租户账户、建 `CreditReservation`、写 `credit_transaction`（`reason=reservation:beauty-industry:seedance`）、提交许可以及建 `viralVideoReplicationJob`（`billingStatus="reserved"`）。改法（两阶段）：① 事务外 `chargeLanqiWallet(requestId = 该次 requestKey)`；② 事务内只做许可提交 + 建 job +（可选的内部审计行），把 `CreditReservation` 的角色由 **job.billingStatus** 承担（`reserved` / `refund_processing` / `refunded`）；③ 任一步失败 → `refundLanqiWallet(同一 requestKey)` 补偿。
- ③ `viral-video-replication-runtime.ts`：与 ④ 同一套（`CreditReservation` + 条件扣减 + 退款），照 ④ 的两阶段改；退款一律 `refundLanqiWallet`，**按原桶退回、同一 requestId 只退一次**，不要自己写 increment。
- 共同注意：`credit-reservations.ts` 仍被美业线使用，**本任务的兰琪路径不要复用它**；兰琪侧一律走 `lanqi-wallet` 的三个函数，等美业线自己切时再收口公共实现。
