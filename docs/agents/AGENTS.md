# 智能体产品目录：Codex 自动接单规则

本文件适用于 `docs/agents/**`，也规定与三个产品系统有关的代码任务如何归类、建卡、开发和交接。

## 1. 用户只描述结果

用户可以直接说“外卖诊断里增加某功能”“创始人 IP 这轮要招学员”“兰琪要让加盟商邀请门店使用”。不要要求用户先判断前端、后端、公共能力、Skill 或数据库。

Codex 必须自行完成：

```text
理解用户结果
→ 识别产品
→ 判断专用/公共层
→ 检查并行冲突
→ 创建或更新任务卡
→ 建立验收和失败测试
→ 最小实现
→ 领域回归
→ 更新 STATUS 与任务卡
```

## 2. 产品路由

| 用户意图 | 产品目录 | 默认任务前缀 |
|---|---|---|
| 外卖平台数据、订单、利润、诊断、问题验证、增长实验、执行回填、效果评估、复盘 | `takeaway-growth` | `TW` |
| 创始人 IP 定位、选题、内容、投流、招商加盟、C 端团购到店、学员招募、合作方招募及转化复盘 | `founder-ip-acquisition` | `FIP` |
| 兰琪知识方法论、美业经营诊断、项目与内部定价、加盟商/被推荐门店、兰琪渠道、算力使用 | `lanqi-beauty` | `LQ` |
| 登录、租户、统一知识权限、文件、会话、计费流水、模型调用、通用组件 | `platform`（记录在 `docs/agents/platform-tasks.md`） | `PLAT` |

一个需求同时命中产品与平台时，仍建立一张以用户结果命名的产品任务卡；任务卡内列出平台子改动。只有可被两个以上产品独立复用、且业务语义完全相同的能力，才抽为公共能力。

## 3. 公共和专用的判断

下列默认属于公共平台：身份与租户隔离、文件存储、知识访问控制、会话/AgentRun、请求取消、幂等扣费、钱包流水、通用错误/加载组件。

下列默认属于产品专用：业务流程状态机、工作地图、Prompt、Skill 契约、业务字段、业务按钮、诊断规则、输出章节、产品知识版本、业务 Eval。

禁止因为两个产品都有“选题”“诊断”“复盘”字样就共享业务实现。只有输入、输出、权限、错误语义完全相同才允许抽取。创始人 IP 获客系统内部的四种获客目标共享 IP 资产和内容基础，但必须使用各自的 Brief、承接路径、转化状态与成功指标。

## 4. 任务与对话

- 一个对话/任务只负责一个主要用户结果，而不是一个按钮，也不是整个智能体。
- 同一智能体同时只允许一个编码任务。
- 不同智能体最多并行两个编码任务，并使用独立 worktree。
- 产品定义、知识整理和 Eval 设计可与另一个产品的编码任务并行。
- 公共热点文件发生重叠时停止并行，按顺序合并和回归。
- Codex 不能静默把当前消息转移到另一个左侧任务。若确实需要新任务，应说明建议标题、原因和应读取的任务卡；用户明确要求后才能创建新任务。

## 5. 开发前后必做

开发前：读取本目录规则、产品五份文档、当前任务卡、质量流程和当前源码；运行最窄基线。

开发后：更新任务卡的修改、测试、风险与后续；更新产品 `STATUS.md`；运行对应 `qa:*` 领域命令与风险匹配的仓库门禁。

## 6. 代码迁移边界

当前生产代码仍有公共巨型文件。新功能优先落入目标产品目录；对旧代码的拆分必须单独建卡、保持行为不变并先建立回归。禁止在业务功能任务中顺手大规模搬迁。

## 7. Skill 候选与运行版本

WorkBuddy 生成或维护的 Skill 永远先进入 candidates/intake/quarantine，不能被产品运行时调用、软链或动态扫描。正式能力必须复制并重新归属为仓库内 Codex 维护版本，拥有独立 manifest、版本、Prompt、合同、Eval、owner/provenance 和升级记录；Web 与 WorkBuddy 只调用这份正式合同。

每个 capability 必须恰好对应一个 active route/workflow/Skill chain。旧 URL 只能兼容导航，历史 AgentRun 只读其保存版本；未知 capability、候选引用、模糊别名、版本漂移和旧模板 fallback 都属于失败关闭项。物理删除运行或历史资产前必须另取精确目标授权。
