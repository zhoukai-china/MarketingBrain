## 三、根因

验收环境是 `controlled_mock` 文本模式（`textProviderMode=controlled_mock`，不真调模型）。三个系统走 `executeBeautyIndustryProductTool` → `invokeSkillViaGateway` → `runAgent` → `assertBeautyWorkflowRuntimeResult`（output-contract）这条链路。

旧代码里，`buildMockReply`（`apps/api/src/services/domestic-chat-provider.ts`）没有为美业各 capability 提供符合 output-contract 的确定性输出，导致三个系统输出校验全部失败。

## 四、分系统修复要求

### 1. 内容系统 content_plan

- 报错 `unverified_runtime_fallback_min_length` 来自 `output-contract.ts` 的 `inspectProviderOutputsAgainstPrimaryContract`，检查 `observedProviderOutputs` 里 provider 输出是否通过 `assertPrimaryContract` 的 min_length。
- 主 skill `baolu_content_creator` 契约 `minLength=760`，requiredSections 含：短结论 / 选题 / 口播逐字稿 / 访谈话术 / 拍摄脚本 / 拍摄注意事项 / 剪辑EDL / 发布标题与话题 / 最佳发布时间 / 评论区引导话术 / 投流建议；requiredTerms 含：开头3秒 / 镜头 / 字幕 / 钩子 / 复盘指标。
- **修复要求**：`buildControlledContentPlanReply` 输出必须 ≥760 字，且十件套栏目与 requiredTerms 逐项出现（当前 16:14 版输出约 1099 字、结构齐全，需实测确认能通过校验）。
- 注意：`createBeautyTextBudgetedProvider` 有 `providerCalls >= 1` 硬限制，`runAgent` 的 quality-repair 二次调用会触发 `beauty_text_budget_provider_call_limit`，因此 mock 输出必须**单次通过**，不能依赖 repair 兜底。

### 2. 复盘系统 video_data_review

- 报错 `rubric_fact_retention_weak` 来自 `packages/agent/src/index.ts` 的 `inspectRubricQuality`（第 3114 行分支）：当输入命中 `isVideoDataTableSource`，会执行 `extractVideoDataTableStats` + `hasVideoDataFactRetention`，若报告未保留核心数值即打阻塞 flag。
- 关键函数：`hasVideoDataFactRetention`（第 9518 行）要求报告里保留：最高播放量、最高完播率、最大3秒留存率、最低平均播放时长、前2个转化值、前2行作品标题。
- **修复要求**：`video_data_review` 的确定性输出（`buildVideoDataTableReviewFallback`）或 `buildControlledVideoDataReply`，必须把上述核心数值写进报告，且不能缺「播放量/完播/互动」关键词。
- 注意：`video_data_review` 在 `runAgent` 第 2057-2083 行走 `buildVideoDataTableReviewFallback` + `video_table_review_direct` 确定性路径，**不经过 provider**；`execution.ts` 里 `evidenceMode=structured_data` 用 `createEvidenceOnlyProvider`（complete 直接抛 `beauty_video_data_provider_forbidden`），两者要一致，别把数据复盘改成走 provider。

### 3. 选题系统 topic_inspiration

- 旧 mock 无 `topic_inspiration` fixture，`buildMockReply` 会落到 `controlled_beauty_capability_fixture_missing` 或通用九件套 fallback。
- 主 skill `baolu_topics` 契约 `minLength=500`，requiredSections 含：最终选题 / 类型 / 来源 / 第一关证据 / 共识层级 / 客资准度 / 适用阶段 / 创作建议 / 配比调整建议。
- **修复要求**：补齐 `buildControlledTopicReply`，且输出必须能被 `applyBeautyTopicVerifiedBrief`（`topic-evidence.ts`）正确替换「本轮主体与目标」元数据，同时四来源、三关筛选、TOP10 结构完整。
- 注意：`execution.ts` 里 `topic_inspiration` 要求必须传 `topicWorkflow`，且走 `assessBeautyTopicEvidence` 评估四来源；`runAgent` 里选题是 single-pass（第 2555-2565 行），不 repair，所以 mock 输出必须一次到位。
