## 验收条件

1. 正常路径：需求提交后同页展示 3 个标题候选、正文、5–8 个 `#` 话题；用户选定标题后，分项复制与整套复制均只含标题/正文/话题。
2. 图片路径：真实报价与积分在确认前显示；确认一次最多创建三张；进度真实，只有整批 3/3 合格才显示图片和逐图下载，刷新/历史可恢复。
3. 失败路径：资料不足在积分前提示；文本失败不保存且释放预留；图片失败不自动重试、补图、换模或追加，失败批次不可下载。
4. 不应发生：客户页面出现模型、Provider、Skill、capability、Prompt、内部质量 detector、演示数字、候选样稿或跨租户资产。
5. 可观测结果事件：唯一 AgentRun、文字一次结算；媒体唯一批次/最多三子任务/整批结算；重复点击幂等，Web 与 WorkBuddy 共用结构化合同。

## 基线与失败证据

- 基线命令：`node scripts/beauty-industry-xhs-workbench-v2-p1-smoke.mjs`
- 修复前失败测试/Eval：`xhs_workbench_v2_component_missing`。
- 现象：当前正式路由和后端合同已完整，但页面仍复用通用双栏工作区；标题不可选择、只有通用“复制客户成品”，图片计划与折叠区暴露构图/检测器细节，实时横幅直接显示模型名，生成进度出现 Provider 品牌名。
- 根因：客户任务编排没有独立的 XHS 呈现边界；后端合同正确，问题位于 Web renderer 与交互层，不是固定路由或 Skill 缺失。
- 浏览器品牌集成红灯：`INVITE_REQUIRED=false` 的本机验收环境中，数据库里的兰琪专属邀请码虽持久化 `brandCode=lanqi`，`/auth/product-invite/validate` 却返回默认品牌。根因是邀请码“非必填”时 `validateInviteCode()` 在读取显式传入的邀请码前直接返回 disabled，错误丢弃服务端品牌授权；这不是品牌配置或页面主题失败。
