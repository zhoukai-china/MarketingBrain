## 本次范围

- 为 URL 安全校验、下载请求、HTTP 响应、Content-Type、大小、路径、目录、图片临时写入、元数据临时写入、原子提交、落盘校验和质量筛查建立显式阶段与稳定错误码。

- 客户页面区分“图片生成失败”与“Provider 已完成但本地保存/检查失败”，隐藏客户资产和下载，账本只释放/补偿一次。

## 验收条件

1. 正常路径：合成 PNG 经 URL、下载、类型、大小、临时写入、双文件原子提交后返回租户元数据；该路径不触发真实网络。
2. 失败路径：各子阶段稳定返回唯一安全码、阶段和 retryable；HTTP 仅保留状态码，不保存 URL；任何失败均无客户资产、无自动恢复入口。
3. 不应发生：不能把所有错误压平为 `asset_persistence_failed`，不能重新查询已终态 Provider，不能二次扣退积分，不能暴露跨租户资产或内部敏感信息。
4. 可观测结果事件：任务参数仅保留 `assetPersistenceStage/code/retryable/httpStatus`；页面显示安全、可行动且不诱导重复付费的终态说明。

## 基线与失败证据

- 真实安全证据：修复后唯一真实终验只创建 1 个 `wan2.7-image` 子任务，Provider=`SUCCEEDED`，随后本地任务以合并码 `asset_persistence_failed` 终止；文件未落盘、v2 检测未运行、后两图未提交、客户资产 0、300 测试积分净 0、Provider 成本保守 ¥0.20。
- 证据边界：旧运行没有持久化 Provider URL、响应或更细阶段，故其具体失败子因保持未知；本任务不做事后猜测。
- 基线命令：`pnpm.cmd beauty-industry:image-persistence-observability-p1-smoke`
- 修复前失败测试/Eval：新增 `scripts/beauty-industry-image-persistence-observability-p1-smoke.ts` 后，首次有效运行稳定失败于 `asset persistence needs an explicit stage contract`，证明原实现缺少显式阶段合同；测试夹具随后保持不变并在修复后转绿。
- 现象、根因和连带影响：资产服务抛出多个字符串错误，媒体路由用单一 `catch` 压平为 `asset_persistence_failed`，并把该终态标为 `canRecover`，既无法定位子阶段，也会允许旧 Provider 任务被再次查询。
