## 验收条件

1. 正常路径：直接任务和 BY-10 TOP10 承接都能在同一专属页生成、卡片化展示、复制、下载 Word、保存与刷新恢复。
2. 失败路径：必要事实缺失先追问；Provider/合同/Word/网络失败、超时、取消、重复点击均有明确终态，失败不误扣且可恢复。
3. 不应发生：不重新调用选题、不串 Skill/租户/行业、不注入跨产品 examples、不输出普通长文或内部字段、不开放视频生成。
4. 可观测结果事件：结构化输入版本、来源 run、固定 route receipt、十件套合同、积分预留/结算/释放、Word 生成/下载归属均可脱敏核对。

## 实现记录

- 产品实现：新增 `BeautyContentTenWorkbench.tsx` 与 `content-workflow.ts`；页面按 V5 正式合同采集选题、目标、人群、平台、形式、时长、表达主体、已确认项目事实与拍摄约束，并用追问卡阻止缺必填项时调用 Provider。

- 交付：十件套按固定顺序卡片化；复制只复制交付正文；Word 下载使用受鉴权 blob，不暴露服务器路径，导出记录绑定租户并在读取时再次校验。
- 竞态与失败：前端同步 ref 阻止同一事件循环重复点击；取消、网络失败和合同失败均明确终态，失败不自动重试；验收环境自 MCP 地址从旧 3011 修正为当前 3016，避免把运行配置漂移误判为 Skill 失败。
- 数据/接口/配置变化：无 Schema、无生产配置；增加版本化 `contentWorkflow` Web/MCP 输入合同和租户受控导出归属。
- 兼容性和回滚点：其他美业工具明确拒绝误传 `contentWorkflow`；FIP `ContentSystemWorkbench` 仅把 Word 下载改为同一鉴权 fetch，不改变其业务文案或合同；专属页和结构化合同可按本任务文件列表独立回滚。
