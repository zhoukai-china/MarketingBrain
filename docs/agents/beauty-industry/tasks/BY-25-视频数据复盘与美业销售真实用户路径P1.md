## 实现记录

- 根因一（视频数据）：`video_table_review_direct` 已正确从服务端解析表格生成确定性正式报告，错误发生在之后的事实保留 Eval。报告为避免泄露/撑坏页面把长标题统一截为 52 字，而 Eval 却要求前两条完整原标题，导致核心数值和报告结构都正确时仍命中 `rubric_fact_retention_weak`。原两行短标题 fixture 没覆盖这一表示差异。
- 根因二（销售）：固定 route、scope 与 Skill 链均正确；`beauty_sales` 的 capability 专属 controlled fixture 标题写成“推荐回复”，正式 `sales_growth_advisor@3.0.0` 要求“话术”，且 fixture 还硬带入未由本轮短输入确认的项目名，因而命中 `missing_contract_terms_话术`。
- 用户同一 CSV 的第二层根因：修复长标题后，直接确定性报告仍被通用行业污染检查拒绝，因为上传表中的作品证据本身合法包含跨行业词；这不是输出模板污染。`video_table_review_direct` 现在只允许逐字出现在当前解析事实源中的行业词通过，内部租户/验收店标识仍阻断；Provider 输出、非直接报告与其他 capability 的污染门禁完全不变。
