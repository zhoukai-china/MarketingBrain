# 桌面自动化能力设计

## 结论

思潼AI增长OS可以开发自己的桌面版，帮助高级版客户完成本地推投放辅助、视频发布辅助、文件分析、报告导出等能力。

但自动化必须遵守三条底线：

- 不替用户保存平台密码。
- 不绕过验证码、短信验证、风控、人脸验证。
- 涉及充值、付款、正式提交投放、正式发布视频时，必须用户确认。

## 推荐产品形态

第一阶段：

```text
H5 + 电脑端Web工作台
```

第二阶段：

```text
小程序 + 电脑端Web工作台
```

第三阶段：

```text
小程序 + 思潼桌面工作台
```

桌面版不应该宣传成“全自动代替用户操作平台”，而应该定义为：

```text
思潼高级工作台：帮用户准备素材、生成计划、检查风险、辅助填写、提醒确认、记录复盘。
```

## 本地推投放辅助

可做：

- 检查门店、城市、人群、素材、预算、线索成本目标。
- 生成投放计划。
- 在用户已登录的平台页面中辅助填写。
- 根据消耗、线索成本、转化情况给出调预算/出价/暂停建议。
- 记录每次操作和结果。

必须用户确认：

- 充值。
- 提交计划。
- 开启正式投放。
- 修改预算。
- 停止正在投放的计划。

不做：

- 绕过平台风控。
- 自动处理验证码。
- 自动使用用户资金。
- 承诺确定ROI。

## 视频自动发布辅助

可做：

- 检查标题、封面、标签、合集、发布时间。
- 根据账号定位生成标题和简介。
- 辅助上传视频和填写发布信息。
- 定时提醒用户发布。
- 发布后抓取基础数据并复盘。

必须用户确认：

- 正式发布。
- 删除视频。
- 修改已经发布的视频信息。
- 发布涉及违规风险的内容。

## 技术路线

桌面端能力分两层：

```text
思潼云端 API
  任务、权限、积分、画像、Agent、审计记录

思潼桌面客户端
  本地文件、浏览器/窗口自动化、用户确认、截图回传、结果同步
```

优先使用官方API；没有官方API或权限不足时，再使用用户本机的可视化辅助操作。

## 任务生命周期

```text
draft
  ↓
requires_user_confirm
  ↓
approved
  ↓
running
  ↓
succeeded / failed / canceled
```

所有任务必须写入 `automation_tasks` 和 `automation_logs`，后台可追溯。

## 桌面端协议

桌面端上线后使用这些接口：

```text
POST /desktop/devices/register
GET  /desktop/tasks/poll
POST /desktop/tasks/:taskId/status
```

注册流程：

```text
用户在H5/工作台登录
  ↓
桌面端用用户token注册设备
  ↓
云端返回 deviceToken
  ↓
桌面端本地安全保存 deviceToken
```

轮询任务：

```text
桌面端带 x-Sitong-device-token
  ↓
GET /desktop/tasks/poll
  ↓
云端分配待执行任务
  ↓
任务状态变为 claimed 或 requires_user_confirm
```

执行回传：

```text
running
  ↓
requires_user_confirm
  ↓
approved / rejected
  ↓
succeeded / failed / canceled
```

桌面端每一步都要回传状态和日志，截图、平台返回信息、错误原因后续作为文件或日志附件扩展。
