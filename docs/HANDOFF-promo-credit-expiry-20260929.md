# HANDOFF · 注册/邀约赠送算力有效期方案（2026-09-29）

> 给：周凯（北京技术合伙人）
> 来自：思潼AI 产品侧（需求定稿，可直按实现）
> 关联：推荐有礼配置（`referral-config.ts` / PLAT-28）、算力钱包双账本（`Wallet.paidBalance / bonusBalance`）

## 一、背景

当前用户增长激励为：**注册即送 100 算力，邀约好友再送 100 算力**。赠送算力（bonusBalance）目前没有明确的到期规则，需要定稿口径并落地。

**先澄清一个概念（避免两套体系混淆）：**

| | 邀约有礼 | 市场合伙人 |
|---|---|---|
| 性质 | **用户端 C2C 推荐逻辑**（老用户拉新用户） | **推广分销逻辑**（渠道合伙人卖货） |
| 奖励 | **算力**（赠送账户） | **人民币分佣**（PartnerCommission → 提现） |
| 配置归属 | 用户增长配置（本方案） | 市场合伙人管理后台（分佣设置） |

两套独立运行，配置键、账本、后台视图都不要混。

## 二、有效期定稿

| 项 | 数值 | 理由 |
|---|---|---|
| 注册送 100 算力 | **30 天到期** | 覆盖美容院/餐饮老板 1 个月决策周期；30 天没用起来 = 自然流失判定，到期清零不引起反感 |
| 邀约好友送 100 算力（发给邀请人） | **90 天到期** | 邀请人是推广员，短到期等于惩罚拉新；90 天封顶防「积分池」无限滚大成负债 |

## 三、实现口径

1. **扣减顺序 FIFO**：扣算力时先扣「离到期最近」的赠送算力。现有算力管理已有「最近赠送到期」列与「不过期扣赠送」逻辑，落地时确认按到期日从近到远扣减即可。
2. **邀请奖励解锁门槛（防刷）**：邀请人的 100 算力**不在好友注册时立即到账**，按「好友首次真实使用（首次 PPU 消耗）」解锁——沿用现有推荐三段奖励（20/40/40）的真实使用门槛，防注册小号刷算力。
3. **到期处理**：到期赠送算力清零（负向流水 type 标记 `bonus_expire`），不做自动延期。
4. **到期提醒（P1，不阻塞）**：到期前 3 天站内/微信提醒。当前无提醒通道，先靠 30 天长度兜底，提醒通道另有排期。

## 四、配置键（不要写死，进配置表）

```
promo.register.credits        = 100    # 注册赠送算力
promo.register.expiry_days    = 30     # 注册赠送有效期（天）
promo.invite.credits          = 100    # 邀约奖励算力（/每位好友）
promo.invite.expiry_days      = 90     # 邀约奖励有效期（天）
```

## 五、验收标准

- [ ] 新注册账户 bonusBalance=100，赠送流水带 `expiresAt = 注册时间 + 30 天`
- [ ] 好友首次真实使用后，邀请人到账 100 算力，`expiresAt = 到账时间 + 90 天`
- [ ] 消耗扣减按赠送到期日 FIFO（先扣快过期的，再扣充值余额）
- [ ] 到期赠送清零并留 `bonus_expire` 负向流水，钱包总额正确
- [ ] 4 个配置键可热调，后台改动无需发版
- [ ] 邀约有礼与合伙人分佣账本完全隔离（算力账本 ≠ PartnerCommission）
