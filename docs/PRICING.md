# 思潼 AI 积分 ↔ 人民币 ↔ 成本换算口径（唯一事实来源）

版本：v1（2026-09-12，PLAT-23 方案 A 落地）。本文件是「一个积分值多少钱、我们的成本怎么算、两者之间怎么换算」的**唯一口径来源**；代码里的常量、注释和契约都以本文件为准。

## 一、先分清三条线（混起来就会定价失真）

### 1）对客售价线（唯一事实来源：`CREDIT_PRICING`）

`packages/shared/src/index.ts` 的 `CREDIT_PRICING`：

- **1 元 = 20 积分**（`ptsPerYuan: 20`），即 **1 积分 = ¥0.05**（`customerPriceCnyPerCredit: 0.05`）。
- 充值档位的基础积分严格等于 `priceCny × 20`（`CreditPack.baseCredits`），多送部分单独记 `bonusCredits`，充值页文案「基准 1 元 = 20 积分」与此一致。
- 口径原则：**售价锚交付价值**。算力成本波动由毛利吸收，不传导到前端价格。

### 2）内部成本线（两张模型价表，分工不同）

| 价表 | 位置 | 单价 | 用途 |
| --- | --- | --- | --- |
| **事后估算**（默认） | `apps/api/src/services/marketplace-cost.ts` | DeepSeek `¥3 / 百万 input`、`¥6 / 百万 output` | 跑完之后估算「这次花了多少」→ 写进账本 `metadata`、做毛利告警 |
| **预算保守** | `apps/api/src/products/beauty-industry/text-budget.ts`（版本 `deepseek-v4-pro-20260824-conservative-cny`） | `¥3.48 / 百万`、`¥6.96 / 百万`（`0.435×8` / `0.87×8`） | 跑之前算**最坏情况预算**与闸门，宁可高估不低估 |

两张表都只用于内部：**不参与对客定价，也绝不进客户端响应**（PLAT-21 / PLAT-22 已把响应里的成本字段摘干净，有契约兜底）。

## 二、成本 → 积分 的换算（只用于内部估算）

```
目标倍数（成本 → 对客营收）：MARKETPLACE_TARGET_COST_TO_REVENUE_MULTIPLE = 100
每积分售价（¥）：            MARKETPLACE_CUSTOMER_PRICE_CNY_PER_CREDIT = CREDIT_PRICING.customerPriceCnyPerCredit = 0.05
成本 → 积分标量：            100 ÷ 0.05 = 2000 积分 / 元成本（浮点下精确等于 2000）

积分 = max(1, ceil(成本(¥) × 2000))
```

- 示例：一次深度复盘实测成本 `¥0.029529` → `60 积分`；`3000/4500 tokens` → `¥0.036` → `72 积分`。
- **修复的历史问题**：旧代码写成 `MARKETPLACE_CREDIT_MARKUP = 20`（注释称「按成本 20 倍定价」）÷ `MARKETPLACE_COMPUTE_COST_CNY_PER_CREDIT = 0.01`，实际效果是 `成本 × 2000 积分`，也就是 **100 倍营收**——名字与事实不符。方案 A 只改表达与推导，**不改数字**。
- 一处必要的精度修正：旧式的「× 20 ÷ 0.01」在 **成本 × 2000 正好是整数**的边界上会因浮点噪声多送 1 积分（例如 `¥0.0035` 给 8 分）。现在的单次乘法返回精确整数（7 分）。这类边界占 0.015%，且只影响内部估算与账本 `metadata`——**对客扣费由 SKU `ppu` 决定，一分未变**。

## 三、变更规则（模型多变、价格多变时的处理方式）

1. **换模型 / 模型涨价**：只改第二张「内部成本线」价表与版本号，**不改对客价格**；成本上升触发毛利告警，由人判断是否需要复审价目。
2. **改对客价格要先问用户**（属动钱的高风险动作，必须单独批准后作为一个独立批次执行）。
3. 前台只显示积分，不显示人民币折算（PLAT-19）；客户侧响应不得出现任何内部成本、供应商或模型字段（PLAT-21 / PLAT-22）。
4. 充值锚「1 元 = 20 积分」不动；要调价就调能力档位价，不去动积分汇率。

## 五、2026-09-17 三条口径（老板拍板，已落地）

### 1）IP 定位智能体 = 固定 400 积分/次（退出成本口径）

- 用户原话：「IP 定位改成按次计费，不按消耗量计费了」；「IP 定位改成 400 积分一次，按次收费（定位本身就是低频使用）固定积分」。
- 货架 `ppu`：`apps/api/src/data/marketplace-v3.json` → `skills["ip-pos"].ppu = 400`。
- 强制固定价：`FIXED_PRICE_SKUS = ["ip-pos"]`，`usesCostBasedPricing()` 先判例外再判白名单 —— 生产 env 的 `BILLING_COST_BASED_SKUS=*` **无法**再把 IP 定位拉回成本口径。
- 为什么不用「成本 × 倍数」：同一件事会因为模型输出长度不同而价格浮动；IP 定位是低频决策类交付，客户要的是「一次多少钱」的确定性。
- 与 2026-09-15「按真实成本计价、不加封顶」的关系：这是**老板明确覆盖**该口径的单点例外，其余 SKU 不变。
- 门禁：`billing:cost-model-smoke`（钉住「`*` 通配也拉不动 ip-pos」）、`marketplace:ip-pos-run-smoke`。

### 2）图片（A+图片）对全部智能体放开，并且真解析

- 用户原话：「确定放开 A+图片」。
- 界面：`accept` 增加 `.webp / .gif / .bmp`；**文件 / 视频 / 语音 / 增强提示词** 4 个入口对所有智能体一致。
- 行为：图片不再「只记文件名」，而是走平台受登录态保护的 `/media/analyze`（qwen-vl）把**画面里能验证的事实**解析进需求单，智能体真的看得到图片内容。
- 计费：按**成功的视觉调用**收 **10 积分/次**（25×，见 §二）；没有成功视觉调用**全额退回、0 收费**；余额不足在调用 Provider 之前 402；识别失败/超时明确提示「本次不扣积分」。
- 服务端无需改动：复用 PLAT-41 已接线的「先预留 → 按实际结算 → 差额退回」链路。

### 3）文案智能体 = 4000 积分/月（每天 5 条），订阅期内不扣积分

- 用户原话：「文案智能体增加按月订阅 4000 积分/月（每天上限输出 5 条文案）用户可以自己选择包月或者按消耗计费，如果选了包月就不再扣积分」；「按单个智能体的逻辑来，有的智能体按次卖、有的按消耗卖、有的同时支持按月订阅（不消耗积分）」。
- 配置：`marketplace-v3.json` → `skills.copy.sub = { credits: 4000, dailyQuota: 5, quota: "每天 5 条文案" }`。
- 数据库：`MarketplaceSku.subscriptionCredits` / `subscriptionDailyQuota`（上架配置）、`MarketplaceSubscription.credits` / `dailyQuota`（下单快照，运营改价不影响已购用户）。迁移 `202609170001_marketplace_subscription_credits`（纯加列）。
- 计费：`POST /market/subscriptions` 扣 4000 积分开通 30 天（**幂等**：已是订阅态返回 `alreadySubscribed`，不重复扣分；余额不足 402 带 `rechargeUrl`）。
  `/market/skus/:sku/run` 先查订阅：**覆盖时 `charge = 0`、不调用钱包扣费**，账本 `refType = marketplace_subscription_usage`、`refId = 订阅 id`，响应带 `pricingMode:"subscription"` 与 `subscription{covered,id,dailyQuota,usedToday,remaining,endDate}`。
- 额度用尽：**409 `marketplace_subscription_quota_exhausted`**（当天 N 次用完、不扣积分、次日 0 点恢复）——**不静默改回按次扣分**。
- 租户隔离：订阅按 `tenantId` 解析，**别人的订阅不会放行你的运行**。
- 根因修复（「生产上所有 SKU 的包月价都是空的」）：`ensureMarketplaceCatalog()` 的 `update` 分支原来把 `subscriptionPriceCny: null` / `subscriptionQuota: null` 写死，每次目录同步都把包月价抹掉。
- 门禁：`marketplace:subscription-smoke`（真实路由 + 真实库 + 真实模型，含额度用尽 409、被拒时不扣分、跨租户不放行）。
- 兼容性：**未订阅的用户行为一字未变**（仍按 `ppu` 或成本口径扣分），旧的人民币口径包月价 `subscriptionPriceCny` 保留但当前为空。
