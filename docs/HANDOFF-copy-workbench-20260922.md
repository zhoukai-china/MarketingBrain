## 4. 访谈式引导逻辑（核心，按访谈规范 v1.0 执行）

**本节全部以《文案智能体-访谈式引导-交接文档.md》为准**，此处只列开发必须记住的要点：

1. **双模式**：默认引导模式；用户明说"直接写/别问了"→ 立刻切直接模式（用已收字段出稿，缺项按默认值）。
2. **7 问字段**（q1_who / q2_goal / q3_audience / q4_material / q5_redline / q6_region / q7_budget），一次只问一题，逐句话术用规范第 4 节原文（开场 GREETING、每题主问/追问/打样/过渡语）。
3. **全局异常处理**：答非所问→换问法重问→再不行给打样；每题最多追问 2 次；一次答多题→按字段归位并跳过已答题；允许跳过（留空走兜底）。
4. **Q4 兜底**：用户没有具体素材 → 追问一次"要不要再补一个真实案例"→ 坚持 → 照出但开头标注"素材待补"；可切"讲观点/教方法"。
5. **Q5 默认红线**：用户说没有 → 套通用红线（不承诺收益/不用极限词/评论区禁"私信·加微信·电话·找我·留个"）。
6. **CONFIRM 复述汇总**：7 题答完智能体原样复述一遍，用户确认后才进入生成；有缺项时提示"地域/预算没填，先按常规"。
7. **completeness 分档**：full（Q1-Q4 全齐）/ standard（缺 Q5-Q7）/ generic（缺 Q4，先追问）/ 缺 Q1-Q3 任一 → **不出稿必须追齐** / direct。生成日志首行注入 `mode=guided · completeness=xx`。
8. **默认值兜底**：平台/时长不填 → "抖音 + 视频号"、60 秒。
9. **JSON 契约**：采集结果按规范第 2.2 节结构注入生成引擎（mode / answers / completeness.level）。
10. **交互形式（用户明确要求）**：**全部自由打字，不做成选择题**。输入框 placeholder 可给参考答法提示，但不得用选项按钮替代用户输入。话术建议做成可配置文案而非硬编码。

## 5. 新增功能需求

### 5.1 语音输入 🎤

- 输入框左侧麦克风按钮，与打字并存。
- **原型实现**：优先浏览器原生 Web Speech API（`SpeechRecognition`，zh-CN），说完自动填入并发送；不支持时降级为"演示模拟"（原型专用）。
- **生产建议**：Web Speech API 只在 Chrome/Edge 可用且依赖网络，建议接**后端语音转写 API**（火山引擎/阿里云 ASR，或复用现有大模型厂商的多模态接口）保证全端可用；录音 → 转写 → 填入输入框（自动发送可选）。按钮需有录音中状态（红色脉冲）与取消能力。
- 头部标签注明"🎤 支持语音输入"。

### 5.2 交付物下载 Word/WPS 版 ⬇

- **背景**：md 文件部分用户手机/电脑打不开，要求交付物支持**一键下载精美排版的 Word/WPS 文档**。
- **原型实现**：纯前端 `Blob`（`application/msword`）生成 .doc：A4 版式、封面（平台名+标题+日期+完整度）、创作简报表（7 问访谈记录原话）、十件套逐件分节（保留时间段标注/动作提示/B-roll/红线警告的配色排版）、页脚品牌。
- **生产建议**：
  - 方案 A（推荐）：后端生成 `python-docx`，可控性强、可做品牌模板、支持手机端微信直接打开。
  - 方案 B：沿用前端 Blob 方案快速上线（Word/WPS 双击可开，零后端改动），后续再切后端。
  - 文件名格式：`金牌文案主笔-内容交付-{内容十件套|单条文案}-{日期}.doc`；轻量模式下载单条文案版。
- 保留"复制全部"按钮；每件单独复制保留。

### 5.3 交付深度（计费，定价待确认）

- 完整十件套：按件计费（**价格表待确认**）。
- 轻量：1 条可直发文案（标题+60秒口播+话题+红线自检），**40 积分**（待确认）。
- 切换深度后简报、占位、费用提示实时联动（原型 `setDepth` 已实现联动逻辑）。

### 5.4 生成与交付区

- 生成日志逐件打勾（✓①…✓⑩），沿用 30 秒轮询 / 25 分钟超时 / 友好报错文案。
- 十件套分组呈现：📋策划区 / ✍️文稿区 / 🎬拍摄区 / 🚀发布区 / 💰投流区（原型用分组 tab 过滤）。
- 每件支持：复制、单独重生成（调用同 run 接口，仅该件）。
- 投流建议件为 `PREVIEW_ONLY` 草案态（生成时标注待补项，确认后由专项投流 skill 执行）。

## 6. 技术落地建议

- **前端**：建议新增工作台路由（如 `/agent/ipzone__copy/workbench`）或在 `AgentChatPage.tsx` 内按 agent 类型分支渲染工作台布局；头像、积分、ICP 页脚沿用现有组件。
- **访谈前置层**：不替代现有生成引擎，在其前面加"访谈采集前置层"，产出 JSON 契约后注入十件套生成流程（与 live script 等其他 agent 的 run 链路一致）。
- **状态管理**：简报字段、completeness、生成进度需在前端持久化（刷新不丢，参考现有会话存储方式）。
- **打样数据**：原型中的演示内容（餐饮招商、12 家直营店、8 个月回本、单店月流水 30 万+、续约率 90%）仅作打样示例。
- **移动端**：原型为桌面双栏；手机端需定义折叠方案（建议：引导对话与简报上下堆叠，简报默认折叠为进度条，交付区全宽）。
- **发布纪律**：遵循 `HANDOFF-tech-partner-20260922.md` 的发布/回滚手册；改动前后核对 `AgentChatPage.tsx` sha256。

## 7. 验收清单

**访谈逻辑**（对应访谈规范第 6 节，全部可测试）：
1. 进入即出现开场白（"7 个问题 + 可跳可停 + 越具体越像你本人"）并征得同意
2. 一次只问一题；每题含追问且追问 ≤2 次
3. Q4 有兜底转换；Q5"没有"套默认红线
4. 答完复述汇总，确认后才生成
5. 缺项按分档处理（缺 Q1-Q3 不出稿；缺 Q4 先追问再兜底标注）
6. 说"别问了直接写"立刻切直接模式
7. 生成引擎收到 2.2 节 JSON 契约
8. 全程无违规引导词（私信/加微信/电话/找我/留个）
9. **全部为自由打字输入，不出现选项按钮**

**工作台功能**：
10. 简报字段随回答实时点亮，completeness 徽章正确
11. 生成日志逐件打勾，30s 轮询、25 分钟超时生效
12. 十件套五组分区正确、单件复制/重生成可用
13. 语音输入可用（至少 Chrome/Edge），有录音中状态，转写结果进入输入框
14. Word 下载可用：Word/WPS 双击打开无乱码、排版完整（封面/简报表/十件套/红线标注）、轻量模式为单条文案版
15. 深度切换联动简报与费用提示；积分扣减正确
16. 页脚"思潼AI商城 · 辽ICP备2025069273号"单行显示
