## 一、上线顺序

1. 不动旧系统入口，保留现有线上版本作为回退。
2. 备份当前 `/os-v2/`、API、生产 env、数据库和 nginx 配置。
3. 在生产 env 中新增 `KNOWLEDGE_CREDENTIALS_KEY` 和 `SKILL_MCP_TOKEN`，密钥只在服务器生成和保存。
4. 部署本地最新版。
5. 先使用两个内部邀请码完成全链路和数据隔离验收。
6. 内部验收通过后，再发三个客户邀请码。
7. 客户经营数据缺失项统一标记 `[待补]`，不暂停系统开发和使用。

## 三、邀请码创建规则

- 每个客户单独一个邀请码。
- `maxUses=1`。
- 明文邀请码只通过私聊发给对应客户，不写入代码、文档或群聊。
- 数据库只保存哈希和脱敏预览。
- 先创建内部A/B，客户码在生产验收通过后再创建。
- 停用旧共享邀请码后再对客户开放新版；生产巡检会阻止剩余次数超过10次的共享码通过。

服务器执行示例：

```bash
set -a
source /etc/Sitong-secrets/Sitong-os-v2.env
set +a

INVITE_CODE="<内部线下生成的明文码>" \
pnpm invite:create -- \
  --label "品牌获客内测-内部A" \
  --plan chain_premium \
  --max-uses 1
```

## 五、首批内测可以暂缓

- 微信登录没有资料时，保持 `WECHAT_AUTH_REQUIRED=false`。
- 微信支付没有完整证书时，保持 `WECHAT_PAY_REQUIRED=false`。
- 采用“邀请码登录＋人工收款＋人工开通”。
- 客户真实经营数据、套餐详情、平台后台数据由客户体验后补充。

## 六、发给客户前人工检查

- 链接能打开，手机和电脑均可使用。
- 客户使用的邀请码只能成功一次。
- 登录后显示正确品牌和套餐。
- 枕水江南默认任务明确写“沈阳外卖平台订单增长”。
- 输出中的未知数据全部为 `[待补]`，不能编造销量、套餐、价格或活动。
- 长输出已按执行卡片、步骤、清单拆段，不出现一整屏密集文字。
- 在已有长交付物后继续追问，不出现“服务暂时忙”；系统自动压缩历史上下文并保留开头、结尾和当前客户资料。
- 客户A看不到客户B的聊天、文件、订单、积分和报告。
- 后台可以查看质量反馈，但不暴露其他客户资料。
