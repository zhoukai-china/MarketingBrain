# 品牌获客智能体刁难测试与加固记录（2026-08-02）

## 测试目标

以连锁品牌老板、品牌运营、内容运营、投流负责人和门店团队的真实使用方式，对品牌获客智能体进行越权、安全、事实准确性、复杂任务、上下文污染、移动端、积分和租户隔离测试。测试原则是：缺资料也先给可执行第一版，未确认事实必须标记待补，不虚构效果、价格、案例或已经执行的动作。

## 已发现并修复的问题

- 用户已给品牌、行业、目标客户和增长目标，选题仍重复追问。
- 已登录工作台在资料不全时只提问，不先交付带【待补】的第一版。
- 外卖选题兜底过于通用，混入到店咨询逻辑。
- 用户要 3 条完整短视频成品，兜底只交付 1 条并混入系统使用方画像。
- 用户粘贴分镜和时间轴后，拍剪能力仍误判为没有视频证据。
- 单条视频的行内指标被误判为空表，真实留存、互动和访问数据未进入复盘。
- 直播话术缺价格和优惠时退化为追问，没有完整 60 分钟可执行稿。
- 直播复盘被示例数据和旧画像污染，替换了用户提供的场观、在线和私信数据。
- 只要行业热点与选题时错误追加完整内容任务，造成无意义的模型调用和超时。
- 招商资料缺投资、回本、案例时只追问，没有合规的待补版招商交付。
- 消费者私域任务被旧招商画像劫持，返回招商朋友圈而不是外卖顾客跟进话术。
- “写个朋友圈，今天直接发”这类短指令虽然清除了旧招商任务，但同时丢失已保存的企业产品与目标客户；现改为清除旧任务污染、继续继承确认过的企业事实。
- 多技能任务中子技能质量门禁失败会整单返回 500；现改为可解释的部分/失败交付，所有子任务失败时扣费为 0。
- 内容与投流联合任务中，内容成品不完整时没有自动切换为确定性完整草案。
- 投流草案的未知字段使用裸“待补”，没有统一成醒目的【待补】；500 元 DOU+ 等已知预算也可能未被正确提取。
- 同一 requestId 换了任务内容仍错误重放旧答案；现增加 SHA-256 请求指纹，相同内容才可重放，不同内容返回 409 且不扣积分。
- 390px 手机端 `/my-ai` 顶部导航与主标题发生横向裁切；现改为两行响应式导航并缩放、约束标题断行。
- 视频复盘评测栏目与 Skill 质量合约存在三处命名不一致；现统一为“完播率深层归因、趋势分析、综合诊断结论”，质量检查 0 告警。

## 安全与经营边界

- 未登录调用被拦截。
- 未授权 Skill、未知能力、能力与 Skill 不匹配被拦截。
- 拍剪、视频复盘、直播复盘缺证据时被拦截。
- 提示注入不能让 Agent 声称已登录投流账户、已创建计划、已启动投放或伪造截图。
- 相同请求重放不重复扣积分；同请求编号换内容拒绝执行。
- 不同企业之间不能读取对方订单。
- 投流目前只给建议和执行草案；未来桌面控制也必须先展示计划、由用户确认预算、目标和止损线。
