## 1. 背景与现状

- **现状**：vidrev 是标准对话页，两个槽位（平台 → 数据），用户上传表格 + 说「复盘」后等 5-10 分钟收 11 章报告（`VidrevReport` 结构化渲染）。
- **痛点**（用户实际反馈 + 2026-09-23 报障 `HANDOFF-vidrev-douyin-daily-export-20260923.md`）：
  1. 用户不知道数据从哪导出、什么形态合格——「按天汇总」表被伪装解析，死在 V7，用户完全不知道该怎么办；
  2. 上传后只有一句「已读取」，字段覆盖、缺什么、影响哪一章，用户看不到；
  3. 11 章报告整块 Markdown，用户不知道重点看哪章、怎么用。
- **已就绪的基础设施**（直接复用，不要重做）：
  - `/vidrev/parse-preview` 预检接口（只解析、不调模型、不消耗积分，已返回 rowCount / fields / platform / period / limitedDimensions）；
  - 后端 `computeVidrevMetrics` 四象限判定与加权口径重算（报告必须照抄）；
  - V1–V9 质量门禁 + 纠错重试 + 校验不过不扣积分；
  - 前端 25 分钟等待 + 30s 轮询 `/market/me/deliverables`；
  - 报告 Word 下载（用户 2026-09-17 已拍板「下载精美 Word」口径）。

### 4.1 fail-closed 上传体检（本次最重要的产品决策）

原型中「按天汇总」演示文件走的是：**入口即拒收**（红色卡片 + 不生成报告 + 不消耗积分 + 明确导出指引），而不是伪装解析后死在 V7。这是 `HANDOFF-vidrev-douyin-daily-export-20260923.md` P0-2 修复建议的工作台化表达：

- 形态判定 = 表头含「日期/投稿量」类列且无「作品标题」列 → 拒收；
- 拒收文案：「检测到按天汇总数据：视频复盘需要逐条作品数据（每行一个作品，含播放/点赞/评论/分享）。请在抖音创作者中心 → 内容管理 → 作品数据 导出，或另存为 CSV 后重新上传。」

### 4.2 体检不扣积分

全程强调「体检不扣积分」「校验不过不扣积分」——只有 V1–V9 全部通过、报告真正交付那一次才消耗积分（现有产品口径）。

## 5. 技术落地建议

- **前端**：建议新增工作台路由（如 `/agent/ipzone__vidrev/workbench`）或在 `AgentChatPage.tsx` 按 agent 类型分支渲染（与文案工作台同一套方案，两个工作台可共用布局组件）；头像、积分、ICP 页脚沿用现有组件。
- **体检面板**：直接消费现有 `/vidrev/parse-preview` 返回（rowCount / fields / platform / period / limitedDimensions / notes），**该接口已存在且已在生产**，前端只是把结果从一句 hint 变成结构化面板；四象限预演可由 parse-preview 返回的 rows 前端算，或在接口返回里追加（建议后者，与后端口径一致）。
- **形态判定**：按 2026-09-23 交接文档 P0-2 在后端 vidrev 入口实现，工作台只消费结果（`ok:false` + 指引文案）；前端不重复实现判定逻辑。
- **成交金额确认**：即现有 `has_revenue_data` 参数（`vidrevParsePreviewSchema` 已有），工作台把它从聊天追问变成显式确认步骤。
- **11 章交付**：`VidrevPayload`（deep）已有完整结构化契约（data_quality / overview / quadrant / content_health / deep_dive / completion_attrib / engagement_depth / trend_alert / patterns / methodology / next_topics），工作台交付区按此渲染分组 tab，每章复制用 `report_markdown` 对应段落。
- **报告解读问答**：done 阶段输入框继续走现有 chat run（上下文带报告），原型里的关键词匹配仅为演示。
- **Word 下载**：沿用现有「下载精美 Word」链路（原型演示用前端 Blob .doc，生产建议保持与 vidrev 现有 Word 交付一致的方案）。
- **状态管理**：体检字段、复盘模式、生成进度在前端持久化（刷新不丢，参考现有会话存储）。
- **移动端（已定稿，按原型实现）**：本稿已按「手机端为主」重做——手机端为三 Tab 单列（💬 复盘引导 / 🩺 体检面板 / 📦 交付报告），≤640px 进一步压缩头部与按钮（开始复盘按钮全宽）；≥960px 展开为双栏同屏。**实现时请以手机端为基准写样式，桌面端作为增强**（与选题策略官工作台 v0.5 同一套做法）。所有用户可见文案不得出现「右侧面板 / 左栏 / 点右侧」等桌面端措辞，一律用 Tab 名指路（如「🩺 体检面板」）。

## 6. 验收清单

**体检流程**：
1. 上传逐条作品明细（抖音/视频号）→ 绿色体检卡片 + 右栏字段点亮 + 字段覆盖 chips + 四象限预演数字正确
2. 上传按天汇总表 → 红色拒收卡片 + 导出指引，不生成、不扣积分，可重新上传
3. 上传小红书/快手等不支持平台 → 明确「只支持抖音和视频号」拒收（现有口径）
4. 「有没有成交金额」确认后，体检面板「成交金额」字段点亮为「有 / 无（ROI 按缺失处理）」
5. 体检状态徽章流转：待上传 → 不通过/待确认成交 → 可复盘

**生成与交付**：
6. 生成日志逐章打勾（✓零~✓十），尾行 V1–V9 门禁；30s 轮询、25 分钟超时沿用
7. 11 章 5 组分区正确：📊1 / 🧭3 / 🔍3 / 📈3 / 🚀1，tab 过滤可用
8. 每章单独复制 / 单独重生成可用；「复制全部」可用
9. 第十章候选选题 ≥2 条、无违禁词
10. Word 下载：Word/WPS 双击可开，封面（平台/周期/条数/模式）+ 11 章完整
11. 交付完成后输入框可继续问报告解读，回答引用报告内具体 video_id 与数字

**工作台通用**：
12. 模式切换（若做快速速读）：深度/速读联动占位、费用提示与交付物
13. 「▶ 自动演示」仅原型功能，生产不实现
14. 页脚「思潼AI商城 · 辽ICP备2025069273号」单行；语音输入（🎤）沿用文案工作台方案（Chrome/Edge 原生，降级提示）

**手机端为主（≤960px 视口，已按原型实测）**：
15. 三 Tab 分段控制器可切换：💬 引导 / 🩺 体检面板 / 📦 交付报告，任一时刻仅一个 Tab 可见

19. 全部文案无「右侧面板 / 点右侧 / 左下」等桌面措辞，均以 Tab 名指路
