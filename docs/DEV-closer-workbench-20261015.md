# 开发技术方案 · 首席成交官工作台（销冠对话引擎）MVP

> **交互基线**：`docs/prototypes/closer-workbench-demo-20261014.html`（v18，纯静态原型，**原型即交互规格**）
> **目标**：把「对话式成交工作台」做成真实功能，前端归属 `apps/web`（商家端后续 Taro 小程序），后端归属 `apps/api/src/products/closer/`
> 原型内数据均为虚构演示数据；「▶ 看效果」演示链 ≈45 秒跑完标准用户旅程，即验收基线

## 1. 原型怎么看

- 本地预览：`python -m http.server 8931 -d docs/prototypes` → `http://127.0.0.1:8931/closer-workbench-demo-20261014.html?v=18`
- 手机端优先（390 视口，单栏切换制 + 底部 TabBar），桌面 ≥960px 左对话右工作台双栏
- 所有控件必须可点（可点性铁律见 project_memory v11 规则），全流程可走通

## 2. 页面结构（原型即规格）

- **桌面双栏**：左对话流（sticky）+ 右工作台卡片列；**移动端**单栏互斥视图（`body.v-chat/.v-work`）+ 底部毛玻璃 TabBar（44px 触控 + safe-area）
- **对话区**：录入入口（截图/语音/粘贴/企微预览）、生成进度卡（gen-wrap 深色管线）、生成等待骨架（skel，模拟 LLM 3-10s）、选项气泡、自由输入路由
- **工作台**：简报组（今日待办/战报/暂不跟/热度）+ 话术报告组（交付卡，最新置顶）+ 客户组（列表+详情页）+ 对练组（场景卡）
- **红点机制**：窄屏对话视图收到交付 → 亮；进工作台 → 清

## 3. 核心功能实现方案

### 3.1 素材录入管道（三入口 → 一条 pipeline）

```
截图(多选批量) ──→ 对象存储 ──→ 多模态LLM(视觉OCR+结构化) ─┐
粘贴文本 ────────→ 直接文本 ──→ LLM 抽取 ─────────────────┼──→ 客户聚类 ──→ 档案字段(带证据引用)
语音录音 ────────→ 对象存储 ──→ ASR(说话人分离) → LLM 抽取 ─┘
企微会话存档(二期) → 会话拉取 → 同上
```

- **批量截图**：前端多选并发上传（限 3 并发），逐张返回识别状态 → 对话流逐条进度（原型 v18 已模拟：≥3 张时最后一张模拟失败，验证失败路径）
- **客户聚类**：抽取结果按手机号/称呼/项目特征合并，多客户时出「归属确认」步（原型 v18 已模拟确认卡），正式版支持拖拽改归属
- **失败路径**：低质量/非聊天截图 → 返回失败态 + 重传/跳过选项，禁止静默吞掉
- 参考现有图片管道架构：`apps/api/src/products/beauty-industry/moments-image.ts`

### 3.2 客户档案（证据分级是红线）

- 档案 = schema 化字段（称呼/联系方式/需求/项目/预算/阶段/异议/热度）+ 每字段挂 `evidence[]`（对话原文引用 + 素材来源 + 时间戳）
- 字段状态机：`空 → 待确认(黄) → 已确认(绿)`；**只有用户原话可直接置绿，LLM 推断一律置黄**
- 「证据不足不填」= schema 校验规则（后端强制），不是提示词约定；话术生成只引用绿字段 + 明示的黄字段
- 存储：`customer_profile`（一客一行 JSONB）+ `profile_evidence`（证据行，含 conversation_id 回溯）

### 3.3 今日战报（派生聚合，不落库）

| 指标 | 取数口径 | 来源 |
|---|---|---|
| 今日跟进动作 | `COUNT(计划 WHERE 执行日=今天 AND 状态=待执行)` | 计划表 |
| 必跟客户 | 当日有动作的高优先级客户去重数 | 计划表 ⋈ 档案 |
| 最热客户 | 当日有动作客户的最高热度区间上限（点击跳档案） | 档案 |
| 待确认信息 | 对应客户待确认证据条数 | 档案证据表 |

- 单店客户 <1000，实时聚合毫秒级；战报数字必须随素材进入动态更新（原型 REAL_N 机制即此口径的演示）
- 每格可点击下钻到明细

### 3.4 跟进计划（依据可溯是差异化卖点）

- LLM 从对话生成计划行：`执行日 / 执行人 / 动作 / 目标 / 进入信号 / 停止条件 / 依据(conversation_id)`
- 状态机：`待执行 → 完成 / 跳过 / 重新计划`；暂不跟的客户=「等触发信号」状态，非删除
- **禁止机械套 3 天/7 天固定模板**——每条计划必须带证据引用，UI 上「依据」可点开看原文
- 存储：`follow_up_plan` + 状态流转日志

### 3.5 异议话术生成（两层 + 红线预审）

1. **检索层**：销冠话术库 RAG（行业 × 异议类型 × 场景），标注来源销冠案例
2. **改写层**：LLM 结合该客户档案（绿字段+明示黄字段）个性化
3. **预审层**：红线规则引擎（主动降价/贬竞品/虚假稀缺/逼单，关键词+分类器双闸）→ 拦截即自动重试，重试仍违规则降级为「安全话术 + 人工提示」
- 对练判分 rubric（原型 `sparJudge` 的规则版）直接复用为预审规则，两套系统一套标准

### 3.6 对练（二期首批）

- LLM 角色扮演：客户人设 = 场景模板 + 该客户档案上下文
- 流式多轮对话；每轮 LLM 按 rubric 判分（接住顾虑/不踩红线/推进动作三维度），总结评分卡
- 判分与角色回复**并行**请求，评分卡最后汇总，避免串行等待
- 扣费：25 算力/场预扣，异常中断自动退还

### 3.7 客户热度（规则起步，不上模型）

- 正信号加权（主动咨询/复购词/主动约时间）+ 负信号衰减（已读不回天数/明确拒绝）
- 输出**区间**（如 60-75°）不输出假精确；依据（命中哪些信号）可展开——可解释性优先于精度

### 3.8 算力计费

- 动作定价表（对齐原型：异议回复 25 / 对练 25 / 报告 25 / 诊断免费）
- `credit_ledger` 流水表 + 幂等键（防重复扣）+ 生成失败自动退款（「出不来结果不扣算力」）
- 账单明细页（原型未做，正式版必须有）；注册赠送 + 充值走支付回调

## 4. UI 需配套的异步改造（真实现撑不住「秒出」）

| 原型假设 | 正式版改造 |
|---|---|
| 所有生成同步秒出 | SSE/WS 流式输出；交付卡前骨架态（原型 v18 skel 已模拟）；批量逐条进度 |
| 演示链定时剧本 | 不存在——换独立 onboarding 引导层，不占对话流 |
| 单客户串行 | 管道先聚类 → 归属确认步（v18 已模拟）→ 分客户出卡 |
| OCR 全成功 | 失败态 + 重传/跳过（v18 已模拟） |
| 全内存态 | 服务端持久化 + 多端同步（店员手机录、老板电脑看）；对话流草稿态 |
| 单店主 | 角色/权限（店长看全店、算力店铺账户）——一期至少留 schema 字段 |

## 5. 红线（必须原样实现，见 project_memory）

1. 禁止个微 Hook/协议号方案（封号风险）；录入仅 截图/粘贴/语音，企微会话存档为二期
2. 档案 AI 自动沉淀，禁止强制手动录入；证据分级；不足不编造
3. 跟单计划每条带依据引用；禁固定时间模板
4. 对练支持自由输入 + 即时判分（评分/亮点/待改进/标准接法）
5. 战报/待办数字必须随真实素材动态更新（禁「传了数据不动」的假象）
6. 商业化叙事（路线图/pitch）禁止出现在产品 UI

## 6. 分期里程碑

| 期 | 范围 | 出口标准 |
|---|---|---|
| **一期（MVP）** | 粘贴+截图录入、客户聚类与归属确认、档案（证据分级）、战报聚合、跟进计划（依据可溯）、异议话术（含红线预审）、算力计费+账单、多端同步 | 商家用自己截图跑通「传→建档→出今日该干啥→拿话术」全闭环 |
| **二期** | 对练场、语音转写、客户热度依据展开、数据看板 | 对练自由输入判分 rubric 上线 |
| **三期** | 企微会话存档自动同步、自动接待建议 | 会话存档合规审批通过 |

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 聊天截图版式多样，OCR 准率不稳 | 多模态 LLM（非纯 OCR）+ 低置信度走「待确认」+ 失败重传路径兜底 |
| 抽取编造（幻觉） | schema 强制 evidence 引用，无引用不入库；抽样人工审核队列 |
| LLM 延迟体验 | 流式 + 骨架 + 分步进度（管线式），全程 3-10s 有反馈 |
| 录音说话人分离错误 | 先做「单人对客户」场景，分离置信度低时提示用户标注 |
| 多客户混淆（张冠李戴） | 聚类确认步强插，不可跳过 |
