# 工作台对话流程模式（IP 定位访谈沉淀版）

> 来源：IP 定位工作台 2026-09-30 的多轮打磨。任何「访谈式收信息 → 确认 → 生成」的工作台都可以直接套用。
> 参考实现：`apps/web/src/marketplace/IpPosWorkbench.tsx` + `apps/api/src/services/ippos-interview-hints.ts`。

## 0. 一图看懂

```
用户回答第 N 题
   │
   ├─ ①立即：用户气泡 + 「正在消化」占位动画（三个点，不是一句会被换掉的话）
   │        同时：清掉上一题的推荐候选（防串题）
   │
   ├─ ②异步：调生成接口（flash 档，≤9s 超时）
   │        输入：已填字段 + 刚答的原话 + 下一题的题干
   │        输出：{ 承接话术, 下一题候选[≤3] }
   │
   ├─ ③消化成型（成功→替换占位；失败→落兜底话术）——都是「一次成型」，无中途换话
   │
   ├─ ④停顿 600ms → 问出第 N+1 题（问题文本上屏）
   │
   └─ ⑤同帧或之后：第 N+1 题的推荐候选才允许渲染（渲染门槛 = 该题已问出）
```

## 1. 模板与模型各管什么（「填空式」分工）

**不动的是模板骨架**（产品资产）：题目、收集哪些字段、提示语、兜底话术。
**模型只填两个槽**：①贴合用户行业的承接话术；②下一题的候选答案。

红线：
- 模型**不能编造事实**——候选只是「可改的示例」，点了**先放进输入框**，用户按回车确认才进简报。模型产出**永不直接落库**。
- 承接话术不编数字、不编事实（模型挂了就落兜底，只是"干"、不会"错"）。

## 2. 数据结构

```ts
interface QOpt  { t: string; d?: string; v: Record<string, string>; digest?: string; rec?: boolean }
interface QFlow { fields: string[]; q: string; hint: string; digest: string; opts?: QOpt[] }
```

- **一题一维度**：8 个简报字段 ↔ 8 个问题一一对应。别把「项目+商业模式」挤成一问。
- **`digest` 放选项级**（`QOpt.digest`），整题的 `digest` 只作回退——多选项题如果共用一份按第一个选项写的消化话术，必然答非所问（踩过的坑）。
- **行业示例选项不能直接落简报**（"XX贴膜…"踩过的坑）：示例值会被 `setBrief` 并进简报 = 别人的生意数据污染用户的交付物。但**冷启动又需要示例**（第一题没有任何已答上下文，模型也没法生成贴合候选）。解法：示例选项加 `example` 标记——**点击先进输入框**让用户改成自己的，回车确认才进简报。**example 只放冷启动第一题**（那时没有任何已答上下文，模型生成不了贴合候选）；后续题目的候选一律由模型生成——静态示例和生成候选同时出现会变成两排重复选项（2026-10-01 用户实测踩中）。结构化选项（平台/深度/出镜方式等与行业无关的）保持直接生效。
- 快填/跳过按钮：**宁可不填，也不填错的**——跳过就留空让用户自己填，文案别写"AI 先铺底稿"。

## 3. 对话节奏（用户原话提炼的三条原则）

1. **上一句没说完，不冒下一句**：消化成型（成功或落兜底）→ 停顿 600ms → 才问下一题。不要固定 800ms 抢跑。
2. **不要一句话中途变成另一句**：先显示占位动画（`.cpw-thinking`），模型回来**一次成型**替换。绝不先显示一句兜底再偷偷换掉。
3. **先出问题，再出推荐回答**：候选带 `q`（题号）标记，渲染门槛 `optsQ === genCandidates.q`——`optsQ` 由 `askQuestion` 设置，问题没问出来候选就永远不会出现。
4. **生成候选存在时替代该题静态选项**（不是并存！）：静态 opts 渲染条件加 `!(genCandidates && genCandidates.q === optsQ && list 非空)`；生成失败（候选为空）才回退静态选项。否则静态示例和生成候选同屏两排（2026-10-01 用户实测连踩两次）。
5. **系统枚举题标 `enum: true`，整体不走 LLM**（2026-10-01 用户：交付深度这种封闭集合直接让用户二选一）：选项是系统定义的封闭值（如 light/full 决定交付链路与价格），不给它生成候选、静态选项永远显示。实现：生成 hints 时若下一题是 enum，`next` 传 null（当前回答的消化话术照常生成）。

## 4. 防卡死的四道保险

| 保险 | 作用 |
|---|---|
| **9s 超时**（`AbortSignal.timeout(9000)`） | 模型拿不到结果 → 落兜底话术照常推进，不让用户对着三个点干等 |
| **runId 防护**（`runIdRef`） | 跳过/重置时 `+1`，飞行中的生成回调发现自己过期就放弃推进（不会把跳出去的用户又拉回访谈） |
| **digestingRef** | 生成进行中自由输入不接——AI 还没问下一题，这时答进去会对不上题 |
| **失败即兜底** | 接口任何失败（非 200 / JSON 不合法 / 抛异常）返回空，前端落写死兜底话术，**访谈永不卡住** |

## 5. 生成接口设计（后端）

- 端点：`POST /market/ip-pos/interview-hints`，**必须登录**（会烧模型钱，不开放给匿名）。
- 模型：复用低风险文本通道（`LANQI_LOW_RISK_TEXT_MODEL`，flash 档），`maxTokens: 600`、`thinkingMode: "disabled"`。成本量级 ≈ 全案的 1%。
- 输出严格 JSON：`{ digest, candidates }`；解析失败/字段超限（候选 ≤3 条、每条 ≤80 字）→ 返回 `{ digest: null, candidates: [] }`。
- 次数策略：**质量优先不省次数**——每次回答后生成一次，贴合当下语境；不做多题合并预生成。

## 6. 生成前体检：建议，不是闸门

- 空槽位本地判定（不花模型钱）；其余交给 LLM 逐槽判 `missing / weak / ok`。
- **发现「缺失/太薄」不许拦人**：体检卡标题写「N 项可以补强（**不强制**）」，底部给两个全宽按钮——`🚀 跳过体检，直接生成`（主）+ `✎ 按提示补充`（次）。小字链接用户看不见（踩过的坑）。
- followup **只能问信息**，禁止让用户背话术/表演/发物料（"有没有过某一段我看看"）。双层防线：
  1. 提示词写硬边界；
  2. **代码级保险**：解析时命中 `/我看看|发一条|拍一条|说一段|背一下|录一段|截图/` 等措辞 → 一律替换为通用补强问法。
- 按钮反馈铁律：**点击必须有可见反馈**。生成前校验期间按钮显示「🔍 生成前校验中…」+ spinner；没填满不要 disabled 静默，点了要报错并列出缺哪些字段名。
- 按钮只在对应阶段渲染（生成按钮只在 confirm 态出现）——**别渲染一个点了会被静默 return 的按钮**。

## 7. E2E 验收经验（踩坑汇总）

- **UI 节奏变了，固定 sleep 会误判**：改成事件驱动——「等问题文本出现再作答」。
- **断言用精确文本**：别拿介绍文案里出现的词当断言（"全案 9 件"在欢迎语里就有），用生成日志的独有短语。
- **跑 E2E 前先核对页面版本**：dev server 被 reap 后供的是陈旧模块，验收全是假象。
- 时序断言范式：100ms 轮询，记录两个事件的首现时刻并比较先后（先问后荐 / 占位先于成型）。

## 8. 对话全程可恢复（草稿缓存，2026-09-30 用户要求）

用户答到一半关掉页面（或算力不足去充值），下次进来要**接着聊**——不是只恢复简报，是**整个对话过程**。

**存什么**：聊天记录（逐条）+ 简报全部字段 + 进度（第几题 / 阶段 / 确认态）+ 未消费的生成候选。键按 skuId 隔离（换智能体不串台本）。

**怎么存**：每次状态变化实时写 localStorage（不是等离开页面才存——用户可能直接杀进程）；`phase === "gen"` 不落盘（生成结果另有 payload 本机找回机制）。

**恢复规则**：

| 存档时阶段 | 恢复后 |
|---|---|
| `ask`（访谈中） | 原样重放对话 + 当前题目重新出选项，用户接着答 |
| `confirm` | 原样重放对话 + 直接进确认态（生成按钮可用） |
| `gen` / `done` | 落到确认态（生成中的活没法续，交付物由 payload 找回机制单独恢复） |

**四个必须注意的坑**：
1. **「正在消化」占位不落盘**——否则恢复时会出现一条永远转圈的假消息。存档前 `messages.filter(m => !m.pending)`。
2. **「已恢复对话」这类提示也不落盘**（ephemeral 临时消息，2026-09-30 用户实测踩中）——提示被存进草稿后，每重进一次就叠一条，用户截图里出现两条。消息加 `ephemeral` 标记，存档时一并过滤；恢复提示每次最多一条。
3. **恢复要幂等**：React StrictMode 会双跑 mount effect，恢复逻辑用 `setMessages(完整数组)` 替换式写入、不要逐条 push，否则恢复提示会重复两条。
4. **★保存 effect 空对话不落盘**：StrictMode 双跑的顺序是 `boot1(恢复成功) → save1(用挂载初期的**空 state** 把真草稿覆盖成空！) → boot2(读到空 → 恢复失败 → 重置)`。保存前判 `messages.length === 0` 直接跳过——凡是「启动恢复 + 持续保存」组合都必须防这条，否则草稿功能看起来"时灵时不灵"。

## 9. 按钮与文案在「浅色宿主」上的可见性（2026-09-30 用户实测）

组件库里的按钮样式往往是为某个底色设计的（如 `.cpw-opt` 近白文字 `#dce8e1` + 透明底，配深色聊天面板）。**把组件挪进另一个底色的容器（浅色体检卡 `#fffaf5`）时，文字会整个隐形**——用户看到的就是"两个空框"。

规则：
- 复用组件到新容器时，**显式重声明文字色 / 底色 / 描边**，不依赖继承；
- 主行动按钮用实底强调色 + 白字；次按钮白底 + 深字 + 描边；
- 验收不只看"按钮在不在"，用 computedStyle 断言颜色对比（`getComputedStyle` 的 bg/color）。

## 10. 状态三态原则

「有没有登录 / 有没有数据」永远三态渲染，不许塌成二态：

| 情形 | 显示 |
|---|---|
| 未登录 | 「未登录 · 登录后可查看…」（判断依据 = 本地会话标志，不是接口是否返回） |
| 有会话、加载中 | 「账号信息加载中…」 |
| 已登录有数据 | 真实数据 |

兜底文案写给用户看的话要人话——「待同步」这种内部术语会被用户当成 bug。


## 11. 进页自动演示模式（2026-10-01，IP定位工作台已实现）

**需求**：新用户一进工作台就看到完整流程怎么走，随时可手动接管。

- **触发条件：进页一律自动演示**（2026-10-01 用户明确：即使页面上已有用户编辑的内容也照常播）——演示相当于「另开一个对话叠在上面，像放视频」，退出演示时整帧还原演示前的现场。
- **⚠ 快照机制（必须做）**：演示开局前抓一帧 `DemoSnapshot`（messages / brief / qi / phase / optsQ / confirmOpts / genCandidates / pieces / answerMd / consumed / payload），退出时**整帧还原**（含本机交付物 `setPayloadView(payload, ·, ·, true)`）。空会话快照才走 `resetAll(true)` 正常开场。
- **⚠ 演示绝不许删真实草稿**：`resetAll` 的「删 localStorage 草稿」必须加 `keepDraft` 开关，演示开局传 true——否则用户刷新页面就会丢掉真实访谈进度（原来是靠「有草稿就不演示」绕开，改成一律演示后这条必须显式防）。
- **铁律：演示零副作用**——①不调任何业务接口（interview-hints / precheck / run 全不碰，纯前端脚本 + 预置数据）；②**绝不写真实草稿**（保存 effect 判 `demoOn` 直接 return，否则演示消息会污染用户的访谈进度）；③不消耗算力；④交付物用预置 mock payload，明示「模拟数据」。
- **实现骨架**：`demoRef`（定时器回调读的真源）+ `demoOn`（横幅渲染）；脚本用 `later()` 挂进 `timersRef`——**停止 = 清 timers + resetAll(true)**，与防卡死保险共用同一套清理机制。每个定时器回调开头判 `demoRef.current`，过期即弃。
- **演示中的交互守卫**：chooseOpt/freeSend/editField/startGen 都要挡（演示的候选/按钮是脚本摆设，点了会与脚本时间线打架）——但**必须给明确 error 提示**（「演示模式中，点停止演示即可接管」），不许无声 return（按钮反馈铁律同样适用于演示）。
- **关键动作要有「被点下去」的实感**：确认态的「开始创作/生成」按钮若只一闪就进生成，用户会以为「按钮和生成阶段都没走」。演示在按钮出现后插一条 `▶ 点了「✨ 开始创作」` 的用户气泡再进生成——把动作演出来，而不是靠用户脑补（2026-10-01 实测反馈）。
- **停止按钮要醒目**：聊天面板顶部常驻横幅（演示状态说明 + 橙色主按钮），停止后立刻回到原状态——接管是瞬间且可见的。按钮文案按快照是否为空变化：「回到我的对话」/「开始我的访谈」，横幅补一句「退出后回到你刚才的对话」降低焦虑。
- **共享实现**：`marketplace/workbench-demo.tsx` 提供 `DemoBar` / `scheduleInterviewDemo` / `scheduleDemoLog`；各工作台只提供 `DemoStep[]`（数据在 `*-demo-data.ts`）和一组适配器（ask / showCandidates / fillBrief / pushUser / pushThinking / replaceMsg）。IP定位、文案、直播三个工作台共用同一套。
- **随时可重播**：顶栏加「▶ 看演示」入口 = `beginDemo(captureCurrent())`（现场抓帧 → 播 → 退出还原）。真实生成进行中（phase==="gen"）禁止开播并给提示，否则演示会清掉在途生成的定时器与结果展示。
- **验收要点**：①演示推进期间草稿 key 始终不存在；②监听 request 断言零业务接口调用；③交付态的断言选**交付卡类名**（`.cpw-pc`），别拿生成占位格（`.cpw-ph`，交付后会被替换掉）。
