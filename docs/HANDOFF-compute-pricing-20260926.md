## 0. 一句话总纲

**系统免费送，智能体 0 元开通，算力自己充值、用多少充多少。** 平台唯一的虚拟货币叫「算力」；不做人民币月订阅；硬件与课程走人民币直购（见 §2）。

---

## 1. 术语与货币（全站改名）

1. 前台全站统一叫**「算力」**，废除「积分」字样：余额、消耗 toast、账单、充值弹层、邀请文案、页脚等所有出现处。单位即「算力」（如：本次消耗 15 算力）。
2. **汇率：1 元 = 10 算力**。实现为后端常量（建议 `COMPUTE_RATE = 10`），**上线后不再调整**；将来让利一律做「充值加赠」活动，不动汇率。
3. 全整数记账，不再出现小数余额。
4. 商品卡、弹层价格旁必须带人民币参考小字：`X 算力 ≈ ¥y`（y = X ÷ 10，保留一位小数，整数则不带小数）。

---

## 2. 计费模式

1. **智能体 0 元开通**：不收开通费、无月费；每次使用按该智能体固定目录价扣算力。
2. **固定目录价**：每个智能体/任务挂固定算力价，与 token 成本解耦；调价是运营主动行为（后台改价+公告），不随成本浮动。
3. **失败不扣费**：任务失败、系统错误、超时**不扣算力**；同一次任务的重试不重复扣费。此条同时写进供应商合同（§9）。
4. **使用前明示**：每次任务发起前展示预计消耗（如「本次预计消耗 15 算力 ≈ ¥1.5」）。
5. **账单逐笔可查**：每笔记录含——智能体、动作摘要、扣减算力、其中赠送/充值构成、时间、余额快照。
6. **消耗保护**：余额低于 50 算力时预警提示；单日累计消耗达阈值（默认 100 算力，可配置）提示确认一次。不做硬性封顶。
7. **扣减顺序**：赠送算力先扣（到期日最近者优先），充值算力后扣（先充先扣）。
8. **例外货架**：AI 硬件、AI 课程为人民币直购商品，不进算力体系；可做「买硬件送算力金」活动（数额运营定，建议默认 200 算力），所送算力属性见 §7。

## 4. 充值

| 档位 | 到账 | 说明 |
|---|---|---|
| ¥100 | 1000 算力 | 随充档 |
| ¥300 | 3000 + 赠 600（合计 3600） | 算力包 |
| ¥1000 | 10000 + 赠 3000（合计 13000） | 算力包 |

1. 赠送部分性质 = 赠送算力（§7），到账时分开记账（余额展示可合并，账单构成可查）。
2. 发票按人民币实际支付额开具；充值加赠活动档位后台可配，不改汇率。

## 5. 存量迁移（⚠️ 已有几个真实付费用户，按 1 元=20 积分充值）

1. **存量余额：按数值 1:1 转为算力**（用户余额数字不变，实际价值翻倍）。对外公告口径：

   > 「积分全面升级为算力！您的余额已 1:1 转换为算力，价值翻倍。」

2. **存量任务价：全部 ÷2**（人民币价不变）。例：旧 29 积分 → 新 15 算力；旧 100 → 50。迁移前导出现行全量价格表，逐条换算成迁移清单，人工复核后执行。
3. 执行步骤：①全量备份（余额、价格、消耗流水）→ ②价格 ÷2 脚本 → ③余额 1:1 转换脚本（保留转换流水，标记 `migration` 来源）→ ④抽样对账（用户余额 ×0.1 = 原人民币价值 ×2）→ ⑤站内公告。
4. 充值记录、发票一律按人民币存档，不受汇率切换影响。
5. 迁移是一次性脚本，须幂等（重复执行不二次改动）。

## 6. 合伙人佣金

1. **只做一级推荐**：佣金只跟直接推荐人结算，绝不做多级。
2. **商品级佣金**：每个 SKU 后台配两个字段——`首充佣金率` / `后续佣金率`。档位参考（可后台按商品微调）：

   | 品类 | 首充佣金率 | 后续佣金率 |
   |---|---|---|
   | 自营智能体 | 30% | 10% |
   | 入驻智能体（高毛利） | 15–20% | 5–8% |
   | 入驻智能体（薄利，如 token+10% 型） | 5–10% | 3% |
   | AI 课程 | 20% | 5% |
   | AI 硬件 | 3–5% | 不抽 |

3. **口径定义**：
   - **首充期** = 被推荐用户首次成功充值后 30 天（天数后台可配）。期内该用户每笔**现金算力**消耗，按所耗商品的**首充佣金率**逐笔计提；期满后按**后续佣金率**。
   - **佣金基数 = 充值算力的实际消耗**；赠送算力（注册礼/裂变/签到/加赠）产生的消耗**不计提**佣金。
4. **兜底铁律（系统校验）**：单笔佣金 ≤ 该笔订单平台毛利的 80%，超限按 80% 封顶——保证任何商品永不倒贴。
5. 结算：按月出佣金账单；退款订单对应佣金扣回；被推荐人与推荐人同设备/同手机号/同支付账号判定为自买，不予结算。
6. 合同保留：费率随平台政策调整（**新客新费率、老客设保护期**）。
7. 需要的能力：邀请关系链绑定、佣金计提流水、月度账单、提现/核销流程、合伙人看板（邀请人数、活跃、佣金明细）。

## 7. 赠送算力统一属性

来源：注册礼 100 / 裂变奖励 / 签到 / 充值加赠 / 买硬件赠送。所有赠送算力统一：

1. **90 天有效期**，到期清零，到期前 3 天提醒；
2. **不进佣金基数**；
3. **限文字类任务**使用（视频生成等高真实成本任务不可用赠送算力支付；如后续放开，限抵 50%）。

## 8. 邀请裂变（邀请有礼）

| 角色 | 规则 |
|---|---|
| 好友（被邀请人） | 扫海报 / 填邀请码 → 注册 + 手机号验证 → **立得 100 算力（实时到账）** |
| 邀请人 | 好友**累计真实消耗满 50 算力** → **得 100 算力（实时到账）** |
| 上限 | 邀请人数不设上限 |

1. 奖励均为赠送算力（§7 属性）。
2. **风控前置 + 追回**（实时到账的前提）：
   - 一机一号去重：同设备 / 同手机号 / 同支付账号只认一个，重复不触发奖励；
   - 单账号单日邀请量异常（阈值后台可配）→ 奖励自动挂起，人工审核后发放；
   - 规则页写明：判定刷量，奖励及已产生收益追回、账户限权。
3. **微信合规**：只奖励「邀请成功 + 有效使用」这个**结果**；禁止「分享到 N 个群/天」类动作奖励（诱导分享封禁风险）。形式用邀请海报 + 邀请码/链接。
4. 数据看板：邀请关系链、各节点状态（已注册/已验证/消耗达标/已发奖）、奖励流水、异常审核队列。

---

## 9. 签到

1. 每日签到得 **5 算力**；**连续签到第 7 天额外奖 30**；周封顶 60 算力；断签重置连签计数。
2. 所得为赠送算力（§7 属性）。
3. 明确不做大额每日打卡（如每天领 100）——会直接杀死充值转化，已运营确认。

---

## 10. 供应商结算

1. **归一**：无论供应商按人民币按次报价，还是按「大模型成本 +10%」计费，全部统一折算成平台算力目录价对用户展示；用户无感知供应商差异。
2. **结算**：供应商侧按调用日志以人民币**月结**；对账字段含——调用单号、智能体、token 用量/次数、协议成本、时间。
3. **合同三锁**：换算率固定；调价须提前 ≥30 天书面通知；失败/重试不重复计费（与 §2.3 对齐）。

## 11. 首页文案与合规

1. Hero 文案：**「智能体 0 元开通 · 用多少算多少 · 不用不花钱」**；主按钮 **「免费开通，送 100 算力」**。
2. 禁用「全站免费」「全部不要钱」等绝对化表述（广告法风险）；免费的是开通权与系统。
3. 每个商品卡标「每次 X 算力起」+ 人民币参考小字。
4. 用户协议必须写明：算力**不可提现、不可转让**；充值退款规则公示；按实际消费开发票；赠送算力有效期与适用范围。
5. 新用户注册礼 100 算力（赠送属性，§7）。

## 12. 开发任务清单

**P0（计费主链路）**
- [ ] 「积分→算力」全站改名 + 汇率常量 `COMPUTE_RATE=10` + 整数记账
- [ ] 余额体系（充值/赠送分账）、逐笔消耗账单、扣减顺序（赠送先扣）
- [ ] 按次固定目录价扣费；失败/重试不扣费；使用前预计消耗展示
- [ ] 八人价目表 + 视频生成两档 SKU 落库
- [ ] 充值档位（100/300/1000 + 加赠）、加赠进赠送账本
- [ ] **存量迁移脚本**（价格 ÷2、余额 1:1，幂等 + 对账，见 §5）

**P0（佣金）**
- [ ] SKU 首充/后续佣金率两字段 + 商品级计提（首充期 30 天口径）
- [ ] 佣金 ≤ 平台毛利 80% 系统校验、赠送消耗不计提、月结账单、退款扣回、自买判定

**P1（增长）**
- [ ] 邀请裂变全链路 + 风控（去重前置/异常挂起/追回条款落地）
- [ ] 签到（5/天、第 7 天 30、周封顶 60、断签重置）
- [ ] 余额预警 + 单日消耗提示
- [ ] 合伙人看板、邀请看板

**验收口径（抽测用例）**
1. 充 ¥300 → 到账 3600（3000 充值 + 600 赠送，账单构成可查）；
2. 消耗顺序：先扣赠送、赠送不足部分自动切充值；
3. 任务失败 → 余额不变、账单无扣费记录；
4. 推荐客户首充后第 31 天的消耗按后续率计提；纯赠送算力消耗 → 佣金为 0；
5. 同设备两账号互邀 → 奖励不触发；
6. 迁移脚本重复执行 → 余额与价格无二次变化；
7. 全站搜索「积分」关键词 → 0 结果。
