# 思潼 AI 增长 OS 总测试计划

本文件定义长期核心验收面。具体任务开始前，Codex 应选择受影响条目并转成可执行验收条件；新增核心能力时同步更新本文件。

## 持续学习专项测试

涉及反馈、行为结果、质量评分、Eval 沉淀或候选发布时，至少执行：

```powershell
pnpm.cmd quality:continuous-smoke
pnpm.cmd qa:fast
```

跨模块交付还必须执行 `pnpm.cmd qa:full`。专项验收必须覆盖：租户隔离、空反馈拒绝、非法事件拒绝、硬门禁不被高评分覆盖、重复问题聚类、样本不足不产生普通候选、脱敏、幂等、候选不自动激活和回滚状态不可被评审接口覆盖。

## 测试环境

| 环境 | 用途 | 允许的动作 |
|---|---|---|
| 本地 demo | 快速开发、确定性回归 | 合成数据，不连接真实客户 |
| 本地 database | 数据持久化、权限、幂等和租户隔离 | 独立测试库和测试租户 |
| 测试/预发布 | E2E、真实集成和发布候选验收 | 测试账号、测试订单、受控外部能力 |
| 生产 | 发布后 smoke 和监控 | 只做预先批准的低风险检查 |

任何报告都要写清实际使用的环境、端口/基址、数据模式和是否调用真实模型或外部服务。

## A. 基础构建与质量资产

- [ ] 项目结构检查通过。
- [ ] Skill 质量资产完整。
- [ ] Eval 文件、Skill contract 和 examples 关系有效。
- [ ] 全仓 TypeScript 类型检查通过。
- [ ] 全仓构建通过。

默认命令：

```powershell
pnpm qa:full
```

## B. 身份、邀请与租户隔离

- [ ] 开发/测试登录按环境策略可用，生产不开放开发登录。
- [ ] 邀请码正常兑换；重复、过期、无效和并发兑换行为正确。
- [ ] 租户 A 无法读取、修改或推断租户 B 的会话、文件、任务、订单、积分、品牌和 Agent 运行。
- [ ] 不同 Agent 会话不会串联。
- [ ] 权限不足返回明确错误，不泄露内部数据。

相关命令：

```powershell
pnpm invite:redemption-smoke
pnpm invite:concurrency-smoke
pnpm beta:smoke
```

`beta:smoke` 需要明确 API 环境、测试令牌/邀请码和安全配置。

## C. Agent 路由、Skill 和编排

- [ ] 典型需求路由到正确 Agent、capability 和 Skill。
- [ ] 任务卡固定能力，自由提问不越过 Agent 白名单。
- [ ] 单步、并行、串行和混合执行顺序正确。
- [ ] 超时、取消、部分失败和质量失败正确降级。
- [ ] 同 requestId 重试保持幂等，不重复执行或扣费；跨租户冲突被拒绝。
- [ ] MCP 必需时不可静默绕过；失败信息可诊断。

相关命令：

```powershell
pnpm qa:regression
pnpm agent:complex-live-eval
```

`agent:complex-live-eval` 涉及真实模型时必须标明成本、环境和运行次数。

## D. 回答质量与事实安全

- [ ] 已确认事实与客户/任务主体一致。
- [ ] 缺失信息标记为【待补】，不编造数据、案例、政策、价格和效果。
- [ ] 不把演示数据、其他客户数据或思潼自身资料当成当前客户事实。
- [ ] 输出包含相应业务契约要求的章节、指标、护栏、止损和下一步。
- [ ] 不声称已经投放、付款、发布、发消息或修改外部系统。
- [ ] 高风险案例至少重复 3 次，无偶发严重违规。

相关命令：

```powershell
pnpm quality:evals
pnpm quality:run-model
pnpm acceptance:acquisition-scenarios
pnpm agent:topic-system-smoke
pnpm agent:topic-research-smoke
```

- [ ] 看板、诊断、实验卡和行动建议使用同一指标口径。

## G. 文件、报告和导出

- [ ] 上传格式、大小和错误提示正确。
- [ ] 文件内容按租户隔离，不通过文件名、URL或导出泄露。
- [ ] 报告内容完整，下载文件可打开。
- [ ] Word/PDF/表格不仅检查生成成功，还要渲染或打开做视觉/公式检查。
- [ ] 临时文件和日志不包含密钥或客户隐私。

## H. 计费、积分与支付

- [ ] 套餐权限在前后端同时执行，不能只靠前端隐藏。
- [ ] 成功、失败、重试、重复回调和并发请求不重复扣费或发放权益。
- [ ] 生产禁止 mock-pay；测试订单与真实订单明确区分。
- [ ] 订单、积分流水和权益变更保持可审计、租户隔离和幂等。
- [ ] 微信配置检查、预下单和回调按测试环境单独验收。

相关命令：

```powershell
pnpm beta:smoke
```

只有在受控测试环境中才增加微信支付相关参数；禁止发起未经批准的真实付款。

## I. Web 页面核心旅程

每次 UI/接口契约变更至少覆盖受影响旅程：

1. 登录/邀请 → 创建或进入工作区。
2. `/my-ai` → 选择 Agent → 新建任务。
3. 填写客户资料 → 发送 → 查看步骤状态 → 打开智能文件 → 下载。
4. 刷新或重新进入 → 会话和结果正确恢复。
5. 文件上传 → 解析/诊断 → 看板 → 行动/实验确认 → 导出。
6. 套餐/积分/订单页面显示与后端权限一致。
7. 内部管理页的 Agent、Skill 版本和 Offer 操作具备权限与确认保护。

每条旅程同时检查：

- [ ] 1440px 左右桌面布局。
- [ ] 390px 左右移动端布局。
- [ ] 加载、空状态、错误、重试、重复点击、刷新和返回。
- [ ] 浏览器控制台无新增错误。
- [ ] 关键请求、状态码和用户提示一致。
- [ ] 页面不显示内部堆栈、密钥、系统提示词或其他客户数据。
