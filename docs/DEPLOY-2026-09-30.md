### 改动

| 文件 | 改动 |
|---|---|
| `apps/api/src/services/wechat-login-bridge.ts` | `WECHAT_BRIDGE_TTL_MS` 5 分钟 → **15 分钟** |
| `apps/web/src/pages/LoginPage.tsx` | 二维码卡片新增**剩余有效期倒计时**（15s 一跳），过期文案改为「二维码有效期 15 分钟，这张已失效。点下面的「刷新二维码」重新生成一张再扫。」 |
| `apps/web/src/styles/store-growth.css` | 新增 `[data-wechat-qr="expired"]` 告警描边 + 标题变红，让失效态一眼可见 |

## 十二、17:50 「两个账号」根因排查（不做数据变更）+ 账号块去 ID

### 用户补充的现象（关键）

- PC 扫码 → 一直是**旧账号**（zk的门店）
- **在微信里一键登录之后** → PC 再扫就是**新账号**（微信测试），旧账号再也不出现
- 刚刚复测仍然如此

### 排查结论

**① 系统侧不存在「同一微信号发两个号」的路径**（逐项排除）：

| 检查项 | 结果 |
|---|---|
| `WECHAT_AUTH_APPID`（当前 + 07-01 ~ 09-19 全部历史备份） | 完全一致 |
| 前端构建期 `VITE_WECHAT_AUTH_APPID`（同上全部备份） | 完全一致 |
| 两套前端产物内嵌 appid（含发布前的 09-28 旧产物） | 完全一致 = `wxf405233d62ec376a` |
| 线上 `/auth/wechat-config` 返回 | 同上 |
| 全库 openid 前 6 位 | 统一为 `o_g_m2`（同一公众号发号特征） |
| 建号路径 | 仅 `auth.ts` 的 `upsert where wechatOpenid`（唯一键）+ bootstrap |

**② 但发现一个真实 bug，很可能就是「看起来像两个账号」的成因**：

`VITE_WECHAT_AUTH_REDIRECT_URI=https://api.lcppch.top/os-v2/wechat-callback` 被注入进**两套**前端（`/etc/baolu-secrets/baolu-os-v2.env`），于是：

- 在 **ai.lcppch.top** 点登录/扫码 → 微信授权后**跨域回调到 `api.lcppch.top/os-v2/wechat-callback`**
- 登录 token 落在 **api.lcppch.top 的 localStorage**
- 用户回到 ai.lcppch.top → **读不到该 token**（跨域隔离）→ 页面仍显示**上一次遗留的登录态（旧账号）**

## 十三、18:25 修正：游客在「我的」页被显示成「已登录」

### 问题

未登录用户打开 `/agents?tab=mine`，账号块显示「我的账号 / 已登录」。

### 原因

第十一节的改动里写了个错误兜底：`accountInfo ? 注册于… : "已登录"`——`accountInfo` 为 null 有两种情形（**未登录** / **已登录但 `/market/me` 还没返回**），却被无条件写成了「已登录」，于是游客看着像已登录。

### 修复（仅前端，未重启后端）

账号块改为三态：

| 情形 | 显示 |
|---|---|
| `accountInfo` 有值 | 真实租户名 + `注册于 yyyy-mm-dd` |
| 本地有会话、接口未返回 | `我的账号` + `账号信息加载中…` |
| 无会话（游客） | `未登录` + `登录后可查看订单、算力与权益` |

### 验证

- 备份：`dist-20260930bak7`、`dist-ai-root-20260930bak7`
- 无头实测（不带 token 访问 `https://ai.lcppch.top/agents?tab=mine`）：账号块显示「**未登录**」，整页不再出现「已登录」✅
