# 思潼 AI 智能 OS 与垂直产品架构

## 已确认产品决策

思潼 AI 智能 OS 是不直接面向终端用户的底层开发与运行平台。身份、租户、权限、知识库、文件、会话、Agent 运行、模型网关、算力计费、审计、Eval、监控和持续改进统一在底层提供。

底层之上是独立垂直产品系统，而不是把所有 Agent 暴露成一个“大后台”：

| 产品系统 | 首期使用者 | 产品内能力/智能体群 |
|---|---|---|
| 创始人 IP 获客系统 | 思潼老客户、创始人及其团队 | IP 资产、选题、内容、投流预览、招商加盟、C 端团购到店、学员招募、合作方招募与复盘 |
| 枕水江南外卖增长系统 | 枕水总部、外卖运营与门店 | 数据、诊断、问题验证、增长实验、执行回填与复盘 |
| 兰琪美业 AI 经营系统 | 兰琪总部、加盟商及授权门店 | 经营诊断、项目与内部定价、获客、成交、培训和经营复盘等专业智能体 |

## 账号与品牌

用户在产品界面看到和注册的是具体产品账号，例如“兰琪美业 AI 经营系统账号”；技术上仍由思潼统一身份服务认证，再授予企业/门店租户、产品系统和产品内 Agent 权限。不得为每个产品复制一套账号、支付、模型密钥或数据库实现。

兰琪初期使用思潼现有域名和基础品牌入口，不在当前阶段建设独立域名。产品授权、租户隔离和数据归属不能依赖域名实现。

## 兰琪未来独立运营

兰琪相关业务初期全部运行在思潼 OS。若未来成立合伙公司，优先把新公司配置为兰琪产品的独立运营方，继续租用思潼 OS，而不是复制整套底层代码。

可向新公司交付的是合同与授权范围内的兰琪产品用户、门店和业务数据导出；思潼底层代码、其他产品数据、其他租户数据、平台密钥与全局模型配置不随数据导出。正式交付前必须确定数据控制者、用户告知/同意、导出字段、历史订单与余额处理、原平台保留/删除策略、审计和回滚方案。

## 长期产品模型

后续平台实现应逐步形成：`ProductSuite`（垂直产品）、`ProductAgent`（产品内智能体）、`TenantProductEntitlement`（租户产品权限）、`ProductKnowledgePolicy`（知识授权）、`ProductModelPolicy`（模型与预算）和 `ProductOperator`（运营主体）。推荐或渠道关系只做归因与结算，不自动授予被推荐租户的数据访问权。
