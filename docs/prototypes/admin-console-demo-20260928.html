交接备注（给周凯的实现口径 · AdminConsolePage.tsx UI升级 v1.4）
  1. 目标页面：现网 /agents/admin = apps/web/src/marketplace/AdminConsolePage.tsx + apps/web/src/styles/admin-console.css。本设计稿对齐该页 7 个 section（推荐归因已并入市场合伙人管理后台，本页不再重复实现），只做 UI 升级与前端功能增强，全部复用已有 API，不新造聚合接口；保留页面原则：仅运营使用、双条件鉴权（x-sitong-admin-token + owner/admin 角色）、每视图展示数据来源 endpoints、错误文案沿用 consoleReadJson 现有人话口径。
  2. 概览仪表盘数据源（四路合并，共享一个 refreshKey）：GET /admin/ops/summary → users{total,createdToday}/tenants{total,createdToday}/subscriptions.activeOrTrialing/billing{paidOrders,pendingOrders,paidAmountCny}/usage{agentRuns,agentRunsToday,...}/quality{feedbackCount,flaggedRuns}/credit算力汇总/topSkills[{skillId,count}]；GET /market/admin/overview → {todayCalls,todayPoints,activeTenants,gmvCny}；充值与账本（见下）。指标卡：用户总数=users.total（今日+createdToday）等，剩余算力=credit 余额合计，注明"充值 x / 赠送 y"。
  3. 近7天充值趋势：前端聚合 GET /admin/recharges?limit=500。口径：仅 status=paid；时间取 paidAt ?? createdAt；按浏览器本地时区 YYYY-MM-DD 分组对 amountCny 求和；从今天往前 7 天补零。空数据/接口报错显示空态文案而非全零柱，并标注「基于最近500条」。可选后端增强（不阻塞）：GET /admin/metrics/daily?days=7 返回按日 {rechargeCny, consumeCredits}，可替换前端聚合。
  4. 近7天消耗趋势：聚合 GET /market/admin/ledger?limit=500 中 type=ppu_consume 的 amountCredits 按日求和；口径同上。
  5. AdminTable 通用表格规格（替换现 DataView 的展示层，useAdminData 数据获取逻辑不动）：① 搜索框跨所有显示列（含 render 后文本）过滤；② 点表头排序 asc→desc→取消循环，numeric 列按数值比、其余 localeCompare(zh-CN)、null 恒末尾；③ 分页每页 10/20/50 可切，默认 10；④ CSV 导出："\\uFEFF" BOM 防中文乱码、含 , " \\n 的单元格加引号且内部 " 翻倍、数值列用原始值（不带 ¥/千分位）、日期 YYYY-MM-DD HH:mm:ss、文件名 admin-{section}-{yyyyMMdd-HHmm}.csv、Blob+a.click+revokeObjectURL；⑤ 表头下「共 N 条」实时联动。
  6. 充值明细：状态 chips 过滤（all/paid/pending/refunded 直接用 query status 参数）；合计条=笔数+合计¥（仅已支付计入合计，待支付单独提示）；列映射 {id,userName,userPhone,tenantNames[],amountCny,basePts,bonusPts,totalPts,method,status,paidAt,createdAt}。
  7. 客户视图：沿用现有列（name/type/industry/city/walletBalance/rechargedCredits/consumedCredits/topAgents/memberCount）；类型列改为「来源」（v1.4）：两值=自营 / 合伙人渠道，注册时即打标（?src= 或推荐码），试用阶段就显示归属、不等付费；合伙人渠道客户小字标注归属合伙人（via，来自 ReferralBinding）；试用状态是另一维度（trial 标记「试用中」小标），与来源正交；topAgents[{name,runs,credits}] 渲染为「名称×次数」小标签（人话规则保留）；行点击详情抽屉=纯前端组装（基本信息+钱包+该客户充值历史(recharges 按 userId 过滤)+常用智能体横条），不新造接口。
  8. 算力管理：沿用现有状态机（搜索/选中/ledger 刷新/grant 弹窗联动），只换 UI；ledger 弹窗保留「智能体」列（现网已有）；手动加算力走 POST /admin/credits/users/:userId/grant，字段：账户(充值/赠送)、积分、备注。
  9. 试用到期 / 失败排查（v1.3 新增两卡，v1.4 加来源列）：① 试用到期提醒=查订阅 status=trialing 且 7 天内到期，按试用期间消耗降序（消耗大=转化概率高优先催），每行带来源列（自营 / 合伙人渠道·归属合伙人）——试用即显示归属，合伙人端「我的客户」同步可见自己的试用客户（ReferralBinding 注册即绑定），跟进状态四态循环（未跟进→已联系→已转化→已放弃）需持久化；② 运行失败记录=近24h 失败/被标记运行明细，建议新增 GET /admin/quality/flagged-runs?hours=24（不阻塞主流程），状态可标记已处理。
  10. 写操作白名单（不新增）：发体验额度 POST /market/admin/trial-grants、建邀请码 POST /admin/invites、SKU 上下架/改价 PATCH /market/admin/skus/:skuId、手动加算力（上述）。操作回执统一 toast（成功绿/失败红文案直出 message）。
  11. 状态→stpill 五色映射：ok/paid/active/通过=绿、pending/waiting/待审核=琥珀、running/进行中=蓝、下架/停用=灰、refunded/已驳回/退款=红。
  12. 自动刷新：概览页 60s 轮询开关（默认开），顶栏显示「最后更新 HH:MM:SS」；切走 section 暂停，写操作后主动 reload 对应视图。dataMode=demo 时概览顶部加「演示数据」徽标，趋势图显示空态。
  13. 样式与移动端：设计变量与组件样式见本文件 <style>（--orange:#E8651A 主色系、卡阴影 0 6px 18px rgba(28,39,51,.05)）；React 落地时新类加 ac- 前缀且调色板 scope 到页面根类（不用 :root，避免污染 Topbar/marketplace 全局样式）；≤860px 侧栏折行、表格 .tbl-wrap 横向滚动必须保留。
  14. 验收清单：① 7 模块导航 ② 概览 8 卡+两趋势+TOP8+动态 ③ 客户搜索/排序/分页/导出/详情抽屉+来源列（自营/合伙人渠道·via）+试用到期跟进（含来源） ④ 充值筛选/合计/导出 ⑤ 算力 ledger 含智能体列+grant 弹窗 ⑥ SKU toggle+改价 ⑦ 失败记录标记 ⑧ 移动端 390px 布局 ⑨ console 零报错 ⑩ 401/403 无权限文案与现网一致。
