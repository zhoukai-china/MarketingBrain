💡 设计说明 · 工作台为什么还要“会提问”

💬按场次类型分流引导

带货和招商是两套完全不同的打法，串场就是事故。第一问先定「这场赚谁的钱」，后面的问题自动切换对应打法——与现有 chat-flows 的 when 分支逻辑一致。

一次只问一个问题、带快捷选项，答案自动点亮右侧开播简报。用户全程知道“我在第几步、还剩几步”。

🧭双轨输入，对话能力不降级

新手走引导问答；老手直接点简报字段改，或在输入框自由打字（“改成 90 分钟”→ 简报自动更新）。

任意时刻可“跳过引导”，简报支持半成品状态保存草稿。

📦十件套分区 + 合规内建

主产出是按时间线推进的主播连续逐字稿（动作标记 + 场控行内小注），节奏表精确到分钟。每件可单独复制、单独重生成。

合规不再是“靠模型自觉”：违禁词预审、“投资有风险”强制嵌入、缺数据标【待补】绝不瞎编。

🔧 工程落地要点 · 给技术合伙人

1️⃣前端

新增路由 /agent/:sku/workbench（AgentChatPage 保留兜底）。工作台 = 分流引导组件 + 开播简报状态 + 话术包渲染三块。

分流问题模板可直接平移 chat-flows.ts 现有 slots 的 when 分支结构（带货/招商两套问题集已在生产）。

2️⃣后端 / 接口

run 接口不变：POST /api/market/skus/:skuId/run；交付轮询复用 /market/me/deliverables（30s 轮询 + 25 分钟超时已在生产验证）。

answer 由纯 Markdown 升级为按 V3 八大件分块的结构化输出，前端按标记渲染卡片；四套轮播话术各自独立分块。

3️⃣计费

轻量（单段话术）沿用现有 SKU 200 积分/次；整场十件套需要新 SKU 或变体（按件计价待定，见下方待确认）。

单件重生成只扣单件积分，需在 run 接口加 piece 参数白名单。

❓ 待确认问题（建议合伙人拍板）
