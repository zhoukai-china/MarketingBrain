📖 口径说明

  • 即时生效：保存后新成交订单立即按新比例计佣；历史订单按成交时点比例快照结算，不追溯重算。
  • 计佣基数：智能体按客户每次使用实际消耗的积分折算人民币（10 积分 = ¥1，与商城算力同口径）计佣，客户用得越多合伙人分得越多；月度订阅与 AI 硬件 / AI 课程按实付金额计佣（表中佣金按标价折算，实际按客户实付）。
  • 退款扣回：客户退款对应佣金自动从合伙人账户扣回，防刷单。
  • 比例上限：建议单商品不超过 50%，特殊活动另行审批（演示环境未强制）。
  • 不参与分佣：OPC 专区商品为演示商品不参与；商品下架或关闭开关后，合伙人端自动隐藏该商品。
⚠️ 本页为设计原型：比例修改仅作用于当前页面演示，不会写入任何环境；技术实现对接点见页面底部交接备注。

🔑 授权与归属口径

  • 一人一码：每位合伙人唯一推广码（ReferralCode），平台链接与商品链接自动携带。
  • 首触归属：客户首次经链接注册即永久绑定（ReferralBinding），后续使用 / 购买任何商品均计佣。
  • 授权管理：合伙人资格经平台授权发放（MarketPartnerGrant），支持续期与回收；回收后历史归属客户沉淀平台。
  • 冻结：风控异常（刷单、投诉）可冻结账号，冻结期间暂停分佣结算与提现，存量佣金核查后释放。

交接备注 · 实现对接点（给技术实现方，评审时可忽略）
  1. 比例配置模型：建议新增 PartnerCommissionRate（skuId、rateBp（基点，20% = 2000）、enabled、updatedBy、updatedAt）+ 操作审计表；合伙人端通过只读接口（如 /api/partner/sku-rates）拉取，无写权限。
  2. 计费对接：apps/api/src/services/billing-cost-model.ts 的 splitPartnerShare() 改为按 skuId 查 PartnerCommissionRate 取比例；PartnerCommission 流水记录成交时点 rate 快照，退款按原快照扣回。
  3. 同步机制：保存成功后可推送（WebSocket / 轮询）刷新合伙人端「工作台 · 分佣产品」；商品下架或关闭「参与分佣」后合伙人端自动隐藏。
  4. 商品范围：智能体（算力消费按 1 元 = 10 算力折算人民币）、AI 硬件 / AI 课程（人民币直购）；OPC 专区演示商品不参与。新商品上架默认不参与分佣，需在本页开启并设置比例。
  5. 关联原型：合伙人端 market-partner-admin-demo-20260923.html（v0.3）——「分佣产品」展示各商品比例、「推广链接」支持分享平台（/r/:code）与单款商品（/r/:code?p=:sku）及团队子链接（?sub=:key）。
  6. 权限与安全：本页仅平台管理员可访问；比例变更记录操作人与时间，支持按月导出对账。
  7. 其余模块（v0.2）：数据总览 = 平台聚合视图（GMV / 分佣支出，读 WalletLedger 与 PartnerCommission 聚合，TOP 与动态为实时查询）；商品管理 = 商城商品上下架与楼层位（复用商城商品表，新增商品默认不参与分佣，需在「分佣设置」开启）；合伙人管理 = ReferralCode / ReferralBinding / MarketPartnerGrant 管理视图（一人一码、首触永久归属、授权续期回收、风控冻结）；佣金流水 = PartnerCommission 平台侧全量视图（pending→settled→withdrawable + 退款扣回负向流水）；提现审核 = PayoutOrder 审核流（待审核→打款中→已打款 / 驳回，建议微信商家转账 API 自动回执对账，超 ¥5,000 二次复核）。
  8. 申请审核（v0.3）：合伙人入驻申请来源为申请落地页 / 官网表单；审核复用 MarketPartnerGrant 状态机（pending → granted / rejected），通过后系统自动创建 ReferralCode（一人一码）+ 发放合伙人后台权限 + 短信通知；拒绝建议记录原因并短信告知；同一手机号 / 微信重复申请做唯一性校验。
  9. 数据总览指标（v0.3）：今日 / 本月 GMV 与今日 / 本月佣金支出读 WalletLedger 与 PartnerCommission 聚合。v0.5 修订：移除算力支出统计——合伙人后台不涉及算力，算力口径只留在统一管理后台；商品消耗 TOP5 改按消耗金额折算（¥）展示。
  10. 合伙人渠道损益（v0.4；v0.6 修订）：净利润 = 收入 − 合伙人佣金，佣金只发生在合伙人渠道。v0.6 起损益表仅列合伙人渠道（ReferralBinding 首触绑定计佣）——短视频 / 直播 / 私域是合伙人自己的三种推广方式，由合伙人在其后台分渠道建链统计（?ch= 打标），不属于平台渠道分组；其余渠道收入零佣金成本，不再列示（已计入 GMV）。收入按实付人民币（智能体确认收入按消耗 10 算力 ≈ ¥1 折算，但本后台只展示人民币，不展示算力）。
  11. 月度结算（v0.4）：新增 MonthlySettlement 模型（月份、合伙人、佣金明细引用、settledAmount、状态机 draft → confirmed → paid，冻结自动 onhold）。每月 1 日定时任务按上月 settled 佣金自动生成 draft；合伙人端「我的 · 月度结算」确认后变 confirmed；平台打款（微信商家转账，回执归档）后变 paid。与提现审核并存：结算单=主动出账，提现=按需支取，打款完成均回写佣金流水已结清。导出对账包=按月打包结算单+佣金明细，供财务归档。
