交接备注 · 实现对接点（给技术实现方，评审时可忽略）
  1. 归因链路：推广链接 /r/:code 落地商城首页并写入推广码；注册时写入绑定。可复用 schema 中已有 ReferralCode / ReferralBinding，推广码 owner 需持有 MarketPartnerGrant（表已存在）。
  2. 分佣计算：apps/api/src/services/billing-cost-model.ts 已预留 PARTNER_SHARE_PERCENT 与 splitPartnerShare()（当前全为 null 待拍板）。v0.2 口径：按商品 SKU 独立设置比例——平台在总后台（原型 platform-admin-demo-20260928.html）按商品配置，合伙人端本页「分佣产品」只读展示；当前演示口径：智能体 20%、AI 硬件 8–10%、AI 课程 15%。
  3. 佣金流水：扣费流水已存在于 WalletLedger / marketplaceLedgerEntry；需新增 PartnerCommission（partnerId、customerId、skuId、sourceType、baseAmountCny、rate（成交时点快照）、commissionCny、status: pending→settled→withdrawable、退款扣回），佣金页面即该表的合伙人端视图。
  4. 提现：需新增 PayoutOrder + 打款通道（建议微信商家转账）+ 平台侧审核后台；本原型只画合伙人端，满 ¥100 可提、T+1 结算、1-3 个工作日打款为建议规则，可调整。
  5. 商品与分享链路（v0.2）：合伙人可分享平台（/r/:code 落地商城首页）或单款商品（/r/:code?p=:sku 直达商品详情页），渠道参数可组合（?ch=:channel&p=:sku）；归因不变——首触注册永久绑定，成交按商品比例计佣。
  6. 团队子链接（v0.3）：仍是一级推广——子链接 = 同一 ReferralCode 名下的推广位（建议在码表加 label 备注名 + subKey 字段，链接形如 /r/:code?sub=:key），客户归属与佣金全部记在主账号合伙人名下，平台只对合伙人一人结算；员工不注册平台账号、不与平台发生资金关系，报酬由合伙人线下自理（合伙人协议需声明）。PartnerCommission 增加 referralSubKey 字段即可支持按链接统计佣金总额与明细。
  7. 来源归属（v0.4）：客户来源注册即定——通过合伙人链接注册即写入「合伙人渠道」归属（复用 ReferralBinding），与是否付费无关；试用期客户同样出现在「我的客户」（紫色「试用中」标签，可筛选），试用期内消耗不计佣。「自营推广」客户归属平台，不进入合伙人列表。
  8. 推广方式与渠道链接（v0.5）：市场合伙人的三种推广方式为短视频 / 直播 / 私域，「推广链接 · 渠道链接管理」默认按三种方式建链（?ch=video|live|private），支持合伙人自建细分渠道（如不同账号、不同直播间，?ch= 打标），分渠道统计点击 / 注册 / 转化 / 佣金；渠道参数可与商品参数组合。归因规则不变：首触注册永久归属该合伙人。
  9. 数据合规：合伙人端只下发脱敏昵称/手机号（如「美**姐」「138****2261」），不下发完整手机号、聊天与工作数据。
