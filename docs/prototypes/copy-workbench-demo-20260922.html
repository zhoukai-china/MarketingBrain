💡 设计说明 · 工作台为什么还要“会提问”

💬用户不会用，就由它先开口

工作台最大的风险是“用户看到一屏表单不知道从哪下手”。所以保留对话式主动提问：一次只问一个问题、带快捷选项，答案自动点亮右侧简报字段。

用户全程知道“我在第几步、还剩几步”——在回答中自然学会工作台的结构。

🧭双轨输入，对话能力不降级

新手走引导问答；老手直接点简报字段改，或在输入框自由打字（“平台换成小红书”→ 简报自动更新）。

任意时刻可“跳过引导”，简报支持半成品状态保存草稿。

📦十件套从“一坨长文”变分区卡片

选题 / 文稿 / 拍摄 / 发布 / 投流五个分区，每件可单独复制、单独重生成；轻量诉求只要 1 条文案，完整诉求再出十件套。

按件计费透明，先看单件价值再决定要不要整包。

🔧 工程落地要点 · 给技术合伙人

1️⃣前端

新增路由 /agent/:sku/workbench（AgentChatPage 保留兜底）。工作台 = 引导问答组件 + 简报状态 + 交付渲染组件三块。

引导问题模板建议第一期前端内置（本原型的问题结构即可作为 schema），后续再做成租户可配置。

2️⃣后端 / 接口

run 接口不变：POST /api/market/skus/:skuId/run；交付轮询复用 /market/me/deliverables（30s 轮询 + 25 分钟前端超时已在生产验证）。

answer 由纯 Markdown 升级为带分区标记的结构化输出，前端按标记渲染成卡片。

3️⃣计费

轻量（1 条文案）沿用现有 SKU 40 积分；完整十件套需要新 SKU 或变体（按件计价待定，见下方待确认）。

单件重生成只扣单件积分，需在 run 接口加 piece 参数白名单。

❓ 待确认问题（建议合伙人拍板）

1. 十件套定价：整包一口价，还是按件累加？单件重生成怎么计费？

2. 引导问题模板是否做成租户级可配置（不同行业专区问题集不同）？

3. 未完成引导就离开，简报草稿是否保存、保存多久？

4. 是否需要「历史简报」：同一产品反复写时直接复用上次简报？
